## 2. 派生字段生成规则

- **档案编号**：`{姓拼音缩写}-{毕业年}-{4 位序号}`，如 `JY-2026-0117`
- **坐标**：常驻城市真实经纬度，格式 `N30.27° / E120.16°`；若简历无城市则默认问用户
- **区块代码注释**：每板块一个 `大写//短横连接`，如 `ARCHIVE//BIO-GRAPHY`、`SHOWCASE//P-01→P-04`（按项目实际数量改）
- **marquee 文案**：`OPEN TO WORK ✦ {职位} ✦ 核心技能 ✦ ...` 循环两遍
- **sec-coord / hero-corner**：`PORTFOLIO — VOL.{年份}`、`FILE NO. {档案编号}`、`● REC`

## 3. 简历信息不全时的补全原则

按"真实感 + 互相咬合"生成虚构补全数据，并在交付说明中告知用户哪些是生成的：

1. **咬合**：数据间必须互相印证——毕设 = 某项目 = 某奖项的获奖作品；实习做的技术栈出现在项目栈里；统计数字与列表条数一致
2. **量化**：每条实习/项目要点至少一个数字（耗时、性能提升、用户量、排名）；数字要合理克制，应届生项目不出现千万级数据
3. **语气**：第一人称、自信但不吹、带一点个人趣味（如"给楼下猫写过识别相册"）；避免"精通""精通 XXX"式套话
4. **技能值**：最高 92（HTML/CSS/JS），语言/框架 84~88，跨端技能 72~80；宁低勿满
5. 若用户简历是真实简历：**只做排版不编造数据**，缺失字段宁可留空或删板块，不虚构（与虚构人物示例不同）
