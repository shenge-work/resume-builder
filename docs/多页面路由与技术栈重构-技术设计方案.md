## 0. 先守住的硬约束（违反任何一条都要重新论证）

这些是项目基因，重构时**不能为了 "现代" 而牺牲**：



| #  | 硬约束                              | 来源 / 理由                                                                                                                                             |
| -- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1 | **file:// 与 Tauri WebView 直开可用** | 单文件版双击即开、`dist-desktop/` 被 Tauri 直接加载；`file://` 下 ES Module 被 CORS 拦、`history.pushState` 行为异常                                                       |
| C2 | **单文件离线版必须继续可构建**                | `tools/build-single.js` 把 CSS/JS 内联成一个 HTML，是产品特色（无网、无 Node、无浏览器都能用）                                                                                |
| C3 | **简历渲染引擎不重写**                    | `renderResumeInner()` + 拖拽排序 + 分页参考线 + 纯文本编辑是核心资产，\~1500 行命令式 DOM，框架化重写风险远大于收益                                                                      |
| C4 | **零后端、零账号体系**                    | ROADMAP「已否决」节明确：定位纯前端工具，数据靠 JSON 导入导出 + 飞书等云笔记同步                                                                                                    |
| C5 | **不新增 npm 依赖、不引入重型构建工具链**        | `git clone && npm start` 必须仍是开发入口；现有 `npm run build` / `verify:assets` 门禁继续生效                                                                       |
| C6 | **全局命名空间模式延续**                   | 现有 `ResumeEditor / ResumeExport / ResumeAudit / ResumeStore / ResumeLibrary / DataSourceAdapter` 都是 `window.Xxx` 挂载；新代码沿用同一约定，不强行转 ES Module（C1 禁止） |
| C7 | **老链接 / 深链不碎**                   | 现有 Tauri 深链、书签、`#` 历史、modal 入口要平滑过渡到路由                                                                                                              |

> 这七条直接否决了「上 React/Vue 全家桶 + Vite + SPA 路由」的直觉方案，下文选型据此展开。

### 1.1 为什么 "简历库" 要从抽屉升级成首页

现在的左抽屉解决的是「在编辑器里切简历」的便利，它**不是产品首页**—— 用户第一次打开 App、或想管理多份简历时，没有落脚点。升级成独立首页后：



* 空简历状态（新用户）有引导，而不是一屏空白纸张

* 多份简历的 "对比 / 复制 / 删除 / 归档" 才有地方放

* 编辑器的左抽屉可以收起，把横向空间还给预览（现在抽屉常驻挤压了纸张宽度）

## 3. 路由设计

### 3.1 为什么选 hash 路由（而不是 history 路由 / 不上框架路由）



| 方案                     | file://                            | Tauri            | 单文件版     | 结论           |
| ---------------------- | ---------------------------------- | ---------------- | -------- | ------------ |
| `history.pushState`    | ❌ file:// 下无 server，刷新 / 直接打开会 404 | ⚠ 需自定义 scheme 兜底 | ❌ 破坏双击打开 | 否            |
| `location.hash`        | ✅ 纯前端，永远可用                         | ✅                | ✅ 内联后照常  | **选**        |
| 框架自带路由（react-router 等） | —                                  | —                | —        | 上框架才有意义，见 §5 |

**hash 路由的代价可接受**：URL 长一点（`index.html#/editor/res_8f3a`），但这本来就是桌面 App，URL 不重要。

### 3.2 路由表



| Hash                               | View              | 入参                        | 说明                   |
| ---------------------------------- | ----------------- | ------------------------- | -------------------- |
| `#/`                               | → 重定向 `#/library` | —                         | 空 hash 默认首页          |
| `#/library`                        | `LibraryView`     | —                         | 首页                   |
| `#/editor/:resumeId`               | `EditorView`      | `resumeId`                | 现状工作台                |
| `#/editor/:resumeId?focus=summary` | `EditorView`      | `resumeId`, `query.focus` | 深链定位到某板块（AI 润色后跳回时用） |
| `#/templates`                      | `TemplatesView`   | —                         | 模板市场                 |
| `#/ai/:resumeId`                   | `AiView`          | `resumeId`                | AI 工作台               |
| `#/tracker`                        | `TrackerView`     | —                         | 投递追踪                 |
| `#/portfolio/:resumeId`            | `PortfolioView`   | `resumeId`                | 官网预览                 |
| `#/settings`                       | `SettingsView`    | —                         | 设置                   |
| `#/history/:resumeId`              | `HistoryView`     | `resumeId`                | 历史版本                 |
| `#/import`                         | `ImportView`      | \`source=pdf              | json                 |
| 其他                                 | `NotFoundView`    | —                         | 404 → 回 `#/library`  |

### 3.3 微型路由核心（约 80 行，零依赖）



```
/\\\* js/router/router.js —— 新增，挂 window.ResumeRouter \\\*/

(function(global){

'use strict';

const routes = \\\[];

let currentView = null;

let currentParams = {};

function compile(pattern){

\&#x20; // '/editor/:resumeId' -> { keys:\\\['resumeId'], re:/^\\\\/editor\\\\/(\\\[^/]+)\\\$/ }

\&#x20; const keys = \\\[];

\&#x20; const re = new RegExp('^' + pattern.replace(/:\\\[^/]+/g, m => {

\&#x20;   keys.push(m.slice(1)); return '(\\\[^/]+)';

\&#x20; }) + '\\\$');

\&#x20; return { keys, re };

}

const ResumeRouter = {

\&#x20; register(pattern, view){ routes.push({ pattern, view, ...compile(pattern) }); },

\&#x20; start(){

\&#x20;   window.addEventListener('hashchange', () => this.resolve());

\&#x20;   this.resolve();

\&#x20; },

\&#x20; navigate(path){ location.hash = '#' + path; },

\&#x20; resolve(){

\&#x20;   const raw = (location.hash || '#/').slice(1) || '/';

\&#x20;   const \\\[path, queryStr] = raw.split('?');

\&#x20;   const query = Object.fromEntries(new URLSearchParams(queryStr || ''));

\&#x20;   for (const r of routes) {

\&#x20;     const m = path.match(r.re);

\&#x20;     if (!m) continue;

\&#x20;     const params = { ...query };

\&#x20;     r.keys.forEach((k, i) => params\\\[k] = decodeURIComponent(m\\\[i+1]));

\&#x20;     // 同 view 不同参数（如 /editor/A → /editor/B）：热更新，不整页重建

\&#x20;     if (currentView === r.view && typeof r.view.onParamsChange === 'function') {

\&#x20;       r.view.onParamsChange(params);

\&#x20;     } else {

\&#x20;       if (currentView && currentView.onLeave) currentView.onLeave();

\&#x20;       currentView = r.view;

\&#x20;       r.view.onEnter(params);

\&#x20;     }

\&#x20;     currentParams = params;

\&#x20;     this.highlightNav(path);

\&#x20;     return;

\&#x20;   }

\&#x20;   console.warn('\\\[router] no match:', path);

\&#x20; },

\&#x20; highlightNav(path){ /\\\* 给 rail 上对应 .nav-item 加 .active \\\*/ },

\&#x20; getParams(){ return currentParams; }

};

global.ResumeRouter = ResumeRouter;

})(window);
```

### 3.4 View 契约（所有页面都遵守这个接口）



```
/\\\* 每个 view 一个文件 js/views/xxx-view.js，挂 window.XxxView \\\*/

const EditorView = {

\&#x20; /\\\* 挂在哪个 DOM 容器（全局唯一 #view-root） \\\*/

\&#x20; root: null,

\&#x20; /\\\* 进入页面：params = { resumeId, focus }

\&#x20;    职责：把本页 DOM 塞进 root，加载数据，绑定事件 \\\*/

\&#x20; async onEnter(params){ /\\\* ... \\\*/ },

\&#x20; /\\\* 路由参数变化（同 view 内 /editor/A → /editor/B），不销毁 DOM \\\*/

\&#x20; onParamsChange(params){ /\\\* 切激活简历，但保留编辑器实例 \\\*/ },

\&#x20; /\\\* 离开页面：解绑事件、暂停定时器、把未保存脏标记交给 store

\&#x20;    ★ 不要在这里销毁 ResumeStore 的数据 —— 切到 AI 再回来内容不能丢 \\\*/

\&#x20; onLeave(){ /\\\* ... \\\*/ }

};
```

**关键设计：视图缓存（keep-alive）**

编辑器是 "重" 页面（拖拽状态、撤销栈、正在输入的框）。切到 AI 再切回来，**不能整页重建**，否则：



* 输入到一半的字段丢了

* 撤销栈清空

* 预览重新渲染闪烁

做法：每个 view 在 `onLeave` 时**只把自己的 root 从 DOM detach 下来（**`root.remove()`**），不销毁**；`onEnter` 时重新 append 回去。`ResumeStore` 本就是全局单例，数据不丢。代价是内存里同时保留几个 view 的 DOM，但 9 个页面里真正重的只有编辑器一个，可接受。

## 5. 技术栈选型

### 5.1 候选方案对比



| 维度              | **A. 原生 IIFE + 微型 hash 路由（推荐）** | B. Vite + Preact       | C. React/Vue 全家桶 |
| --------------- | ------------------------------- | ---------------------- | ---------------- |
| file:// 直开      | ✅ hash 路由零配置                    | ⚠ 需把 build 产物配成相对路径    | ⚠ 同 B            |
| 单文件离线版          | ✅ 现有 `build-single.js` 继续       | ❌/⚠ 要重写打包脚本            | ❌                |
| 简历渲染引擎改造        | ✅ **零改动**                       | ⚠ 要包成组件（仍可保留纯函数）       | ❌ 几乎重写           |
| 新增依赖            | 0（路由自己写～80 行）                   | +preact 3KB + vite 工具链 | +40KB+           |
| 构建工具            | 保持现状                            | 引入 Vite，开发流程大变         | 同 B              |
| AI 流式 / Diff UI | 够用（命令式 DOM 拼接）                  | 舒适                     | 舒适               |
| 学习成本            | ✅ 现有团队熟                         | 低                      | 高                |
| 包体积             | +2KB                            | +5KB                   | +50KB            |
| 与 C6（命名空间模式）兼容  | ✅                               | ⚠ 风格冲突                 | ❌                |
| 与 C5（不引入构建工具）兼容 | ✅                               | ❌                      | ❌                |

### 5.2 结论：选 A，预留升级到 B 的退路

**现在选 A 的理由**：



1. 项目规模（\~5k 行 JS，目标 9 个页面）远没到需要虚拟 DOM diff 的程度

2. 简历渲染引擎是命令式字符串拼接（`h += ...`），硬塞进 JSX / 模板字符串反而别扭

3. 七条硬约束里 C1/C2/C3/C5/C6 全部指向 "别动工具链、别动渲染引擎"

4. 微型路由 + view 分层已经能解决 "多页面" 的核心诉求，**不引入任何新依赖**

**什么时候升级到 B（Vite + Preact）**：



* AI 工作台演进到需要复杂的状态联动（流式 token、Diff 树、多面板实时同步），原生命令式代码开始难维护时

* 此时退路依然清晰：`ResumeStore / ResumeLibrary / DataSourceAdapter` 本就是纯 JS 单例，不依赖任何 UI 框架，Preact 只替换 view 层，store 层原样复用

* Preact（3KB）可继续内联进单文件版，不破坏 C2

**永远不选 C**：项目是零依赖离线工具，引入 40KB+ 框架得不偿失，也违背产品基因。

### 5.3 依赖清单（本方案新增）



| 新增                    | 用途                     | 体积       |
| --------------------- | ---------------------- | -------- |
| `js/router/router.js` | hash 路由 + view 挂载      | \~2KB    |
| `js/router/layout.js` | 全局 rail /mobile tabbar | \~1KB    |
| `js/views/*-view.js`  | 9 个页面                  | 每个 1–5KB |

**不新增任何 npm 包**。vendor/ 目录不加新文件。

## 8. 风险与边界



| 风险                             | 应对                                                       |
| ------------------------------ | -------------------------------------------------------- |
| 视图缓存导致内存累积                     | 只 keep-alive `EditorView` 一个重页面；其余 view `onLeave` 时真销毁   |
| Tauri 深链自定义 scheme             | P0 验收时专门测 `tauri://open#/editor/xxx` 是否正确路由              |
| hash 变化触发 `beforeunload` 脏检查误报 | 路由跳转前先 `ResumeStore.flush()` 把脏数据写回，再 navigate           |
| 移动端浏览器返回手势                     | hash 路由天然走浏览器历史，无需额外处理                                   |
| 多人 / 多设备同时改                    | 沿用 [多简历方案](./多简历与多数据源-技术设计方案.md) 的字段级 3-way merge，路由层不负责 |
| 误上框架                           | 本文档的选型结论锁定 A；要切 B 必须先更新本文档并说明触发条件                        |

### 明确不做



* ❌ 不引入 React/Vue/Angular，不引入 Vite/Webpack/Rollup

* ❌ 不做服务端、账号、云同步（C4）

* ❌ 不重写简历渲染引擎（C3）

* ❌ 不把 view 拆成 ES Module（C1 禁止；等将来真要上 Vite 时再一起转）

* ❌ 不在本阶段实现任何新业务功能（P3 起才按各业务设计文档推进）
