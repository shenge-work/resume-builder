## 一、视频中的 Skill 生态提取（重点）

这是本视频最值得借鉴的部分：它**不是**教人写一段提示词，而是用一个**技能市场里的预建技能**把整套流程固化下来。

### 1.1 技能广场（Skill Marketplace）

TeleAgent 桌面版内置「技能广场」，界面要素：
- 两个标签页：**技能广场 / 我的技能**。
- 分类筛选：全部 / 精选技能 / 校园专区 / 量子专区；另有「全部场景」筛选与「导入技能」按钮。
- 技能卡片字段：技能名、一句话描述、依赖标签（如「应用连接」）、发布时间、「已添加」状态。
- 同屏可见的其他技能示例：Excel 助手、创建网页、PPT 助手、Word 文档助手、金山文档助手、Windows 电脑安全检查、湘办通万能助手、新生助手等——技能是可插拔、可搜索、可导入的资产。

### 1.2 本视频用到的两个核心技能

**A.「求职网站生成器」（portfolio-website-generator）**
- 卡片原话：「**提供个人简历，一键生成新粗野主义风格的求职作品集网站（超大姓名排版、立体档案卡、项…）**」
- 发布于 2026.9.10，状态「已添加」。
- 产物：`index.html` + `resume.html` + `css/style.css` 三个文件，放在 `portfolio/<用户名>/` 目录，双击 `index.html` 即可本地预览。
- 带**技能自进化**：视频末尾提示「portfolio-website-generator 技能更新候选还在等待您的『选择』，随时回『查看』或『放弃』」——技能本身会收到更新版本，由用户决定是否升级。

**B.「求职助手」**
- 卡片原话（tooltip）：「**AI 全流程求职助手，支持目标岗位调研、简历优化、面试准备等求职环节。通过分析岗位需求，匹配个人经历、优化简历表达，并提供针对性面试训练，帮助用户提升求职竞争力，获得理想 Offer。**」
- 视频里它承担「读资料 → 梳理个人介绍」这一步，并且**自带执行协议**（见 1.3）。

### 1.3 技能内置的「可靠性协议」（执行日志里观察到的）

这是最值得抄的设计——技能不是闷头生成，而是先体检再动手：
1. **输入体检**：先清点收到的文件（Excel 案例数据、PPT 作品集、4 张项目截图），逐项确认存在。
2. **缺口澄清**：用户没指定目标岗位时，**不瞎猜**，明确说明「从资料看方向是『前端开发』」，再继续。
3. **并行处理**：并行读取 Excel 与 PPT；缺解析库时先自动安装再读。
4. **数据交叉校验**：从 PDF、PPT（含演讲者备注）、Excel **三处交叉比对**数字，要求「口径完全一致、无矛盾项」。
5. **敏感信息占位**：真实联系方式用 `example.com` 域名占位，并注明「对外投递前需替换」；GitHub Stars 等数字标注为「2026 年 9 月快照」。
6. **自校验报告**：生成后汇报「23 个标题 / 4 个表格 / 4 张图片全部嵌入、59/59 关键数据点覆盖」，并坦白「本机缺 LibreOffice 无法转图片目检版式」。
7. **修改后回归验证**：改完字体自动汇报「黑体 900 加载正常、手机端 390px 无横向滚动、全站零报错」。

### 1.4 交互确认 4 问（生成前对齐）

技能在真正写代码前，弹一轮结构化问答：
1. **方案总体确认**：按方案执行（推荐）/ 需要调整 / 自定义输入。
2. **简历下载形式**：如「简历页 + Word 下载」。
3. **形象照设定**：用 AI 生成形象照还是上传真实照片。
4. **交付位置**：默认「个人资料文件夹内」。

### 1.5 卖点总结（视频怎么吹的）

- 「超 400k Token 上下文」——能记住多轮频繁变化的需求，改字、改字体、改结构都不串。
- 精确到**文件级**修改（index / resume / css 三处还原，「宋体引用零残留」）。
- 同一套能力既能做个人求职站，也能做一人公司业务官网。

> **对本项目的启示**：这套「技能 = 固定流程 + 输入体检 + 交叉校验 + 生成前确认 + 修改后回归」的协议，
> 比「一段提示词」重要得多。本项目将来做 AI 能力时，应当把它沉淀成**可复用的流程规则**，而不是一次性 prompt。

## 三、不做什么（去糟粕 + 诚实定位）

视频评论区的高赞反方观点非常清醒，必须吸收，避免做出一个「自嗨型作品集」：

- **HR 根本不会点开你的个人网站**（HR 一天看几百份简历，只想直接看 PDF / 一页纸 doc；「普通职位连 PPT 都不看，一页纸 doc 最受欢迎」）。
  → **个人官网不替代 PDF 简历**。它的真实使用场景是：① 招聘软件**沟通中**附链接（视频自己演示的就是这个，不是让 HR 主动去搜）；② 技术岗/设计岗/作品集展示；③ HR 初筛通过后、发给直属业务面试官看的深度页。导出时文案要诚实，不要宣传「靠它拿 offer」。
- **个人隐私底裤全被扒**（评论原话）。
  → 导出官网时**默认关闭敏感字段**（手机号、身份证、详细住址、期望薪资），提供「隐私脱敏开关」，公开部署前二次确认。**这一条视频里的做法本身就对**：联系方式用 `example.com` 占位、提醒对外投递前替换——我们直接吸收成产品默认值。PDF 简历才是含完整联系方式的那一份。
- **形象照/项目封面靠 AI 瞎编**。
  → 本项目坚持「**AI 永不直接落笔、事实性数据必须可追溯**」（与 AI辅助写简历-技术设计方案.md 的护栏一致）：官网里的数字、公司名、时间线必须来自已录入的简历数据，不允许 AI 编造；封面图用用户上传的真实作品截图，不留 AI 生成占位图。视频里「形象照设定」那一步，本项目默认**不上传/不生成**真人照，除非用户明确选择。
- **不绑定 TeleAgent / 任何云端 Agent，也不做技能市场**。
  → 本项目气质是**零后端、数据全在本机**。「简历→官网」导出纯前端完成；AI 梳理部分走 AI辅助写简历-技术设计方案.md 已定的「本地 Node 转发层」，不要求用户注册任何平台。技能市场/技能自进化只记录思路，本期不做。

## 四、产品定位

> **一句话**：在现有简历编辑器里，多一个「**导出 → 个人官网**」按钮，把同一份结构化简历数据渲染成一个响应式、可公开部署的单页网站，同时保留「下载 PDF 简历」出口，并给一段能直接复制到招聘软件的附言。

- **不是**：一个在线建站平台、一个 AI 生成器、一个需要注册的 SaaS。
- **是**：本地简历数据的**第五种渲染格式**，和 PDF/Word/MD/JSON 平级。
- **数据同源**：官网和 PDF 读的是同一份 `data/resume.json`，改一处处处同步——这是本项目相对视频里「AI 生成完就散成一堆 html/css」的**核心优势**。

## 五、能力设计

### 5.1 「导出为个人官网」产物形态

- 输出**单个自包含 HTML 文件**（内联 CSS/JS，图片以 base64 或用户上传路径相对引用），与现有「单文件 HTML 导出」同一构建管线。视频拆成 `index.html` + `resume.html` + `css/style.css` 三文件，**本项目单文件版更优**，无需多文件协作。
- 内置**响应式断点**：桌面双栏（左档案卡 / 右正文），手机单栏纵向堆叠——直接满足视频里「适配手机端（390px 无横向滚动）」的要求。
- 页头右上角固定 `下载 PDF 简历` 按钮，调用现有 `POST /api/pdf` 静默导出链路（浏览器环境）或 Tauri 原生保存命令（App 环境，见 [App导出不落盘问题-根因与改造方案.md](./App导出不落盘问题-根因与改造方案.md)）。
- 生成后给用户两样东西：① **部署提示**（丢 GitHub Pages / Vercel / Netlify 即可公开，附「公开前请检查脱敏开关」提醒）；② **一段可复制到招聘软件的附言**（如「这是我的个人网站，您看看：<链接>」）。

### 5.2 官网专属 schema 扩展（纯增量，向后兼容）

在 `template.json` 的 `sections[]` 上增量，**不改动现有字段**：

```jsonc
{
  "id": "s_kpi",
  "type": "kpi-band",            // 新增：首屏大数字带
  "title": "关键数据",
  "items": [
    { "value": "1200+", "label": "GitHub Stars" },
    { "value": "4",     "label": "完整上线项目" },
    { "value": "2",     "label": "大厂实习" },
    { "value": "8",     "label": "获奖与证书" }
  ]
}
```

```jsonc
{
  "id": "s_projects",
  "type": "project-cards",       // 新增：项目卡片墙（现有 project 时间线保留）
  "title": "项目作品",
  "cards": [
    {
      "name": "拾光 LIGHTDECK",
      "cover": "data/uploads/lightdeck.png",  // 用户上传，不允许 AI 生成占位
      "metrics": ["留存 +21%", "PV 82万"],
      "stack": ["React", "Node.js", "Redis"],
      "before": "首屏加载 4.2s",   // 可选：证据链三元组
      "after":  "首屏加载 1.1s",
      "approach": "图片分片 + 接口预取"
    }
  ]
}
```

- 视频里「档案结构（9 大板块）」画面可见 7 项：**核心指标 / 定位与优势 / 教育·技能矩阵 / 实习经历 / 项目档案 / 性能优化战绩 / 能力画像**；其余两项（求职意向、联系方式等）从官网顶部导航推断。本项目按需选取，不必硬凑 9 个。
- PDF / Word 视图下：`kpi-band` 渲染为一行小数字；`project-cards` 退回现有时间线样式；`before/after/approach` 折叠为一行小字。**保证 PDF 版不被官网版式带偏。**

### 5.3 官网主题（新粗野主义 / 杂志风）

- 与 ROADMAP「多模板/主题」合并实施，官网主题是第一个落地主题。
- 视频设计规范原话要点：参考**潮流杂志、新粗野主义、个人 ID 档案**风格；黑 1px 实线框、黑色粗线框、亮橙色 + 少量蓝色作强调色；首屏超大中英文姓名排版；左侧职业定位/个人简介/按钮，右侧带编号、状态标签、资料字段的**立体个人档案卡**；作品用黑色卡片，hover 时微上浮、错位、旋转并出现项目编号与「查看详情」按钮；加入横向滚动 marquee、印章标签、状态灯、坐标、编号、像素箭头等细节，但不杂乱。
- 动效克制：卡片 hover 微上浮即可，**不做**视频里那种全屏旋转/错位，避免面试官加载一张本地图都卡。
- 严格沿用本项目「视觉黑白灰」底线的**例外**：官网主题允许一个强调色变量，其余仍中性。

### 5.4 隐私脱敏开关

- 导出官网前弹确认：列出将公开的字段（姓名、城市、邮箱、GitHub、作品集链接默认公开；手机号、详细住址、身份证、期望薪资默认隐藏）。
- **直接吸收视频做法**：占位邮箱用 `example.com`，并明确提示「公开部署前请替换为真实联系方式」。
- 开关状态写进 `sync.config`，下次记住。
- PDF 导出**不受**该开关影响，始终含完整联系方式——官网和 PDF 是两个信任等级的产物。

### 5.5 生成前对齐向导（远期，依赖 AI 落地）

将来接 AI 能力时，把视频的「交互确认 4 问」做成导出向导：
1. 方案总体确认（按方案 / 需调整 / 自定义）；
2. 简历下载形式（官网内嵌 PDF 下载 / 仅文字 / 无）；
3. 形象照（不上传 / 上传真实照，**不提供 AI 生成**）；
4. 交付位置（浏览器下载 / 项目目录）。
配合「输入体检 → 交叉校验 → 生成 → 回归验证」的完整协议（见第一节），沿用 AI辅助写简历-技术设计方案.md「AI 永不直接落笔、必经 Diff 审阅」。

## 八、参考实现拆解：resume.nodetime.top（最接近的成熟落地）

> 访问于 2026-09-19。这是一位 5 年+ Java/AI 架构师「杨胜」的在线简历站，
> 作者称它是「2026.09 独立设计开发并部署上线的全栈项目」。它和小红书视频里的「江屿」是**同一种产物**（个人求职单页站），
> 但走了完全不同的技术路线——视频是「AI 生成静态文件」，这个是「**全栈 Web 应用 + 内嵌 AI 问答**」。
> 两边对照着看，最能看清「官网导出」这件事的产品边界。

### 8.1 它长什么样（视觉与信息架构）

- **深色科技风**（和视频的米色新粗野主义完全不同）：纯黑底 + 首屏深蓝紫「星云/墨水」渐变 + 蓝色主按钮，开发者审美。
- **单页滚动 + 顶部固定导航**：左名字、中「经历 / 技能 / 项目」、右「联系 + 刷新图标」；右侧一列**章节进度小圆点**，当前章节高亮。
- **首屏**：超大居中姓名 → 副标题 → 三个胶囊徽章（如「CCode 72★作者 / 日均20亿Token Agent系统 / 7人技术组负责人」）→ 位置与求职状态（深圳 · 期望深圳/广州 · 在职）→ 一段自我介绍 → 三个按钮（**联系我** / GitHub / **下载 PDF**）。
- **四大数字带**：5 年+ 后端 / 20 亿+ Token 日 / 8000 万+ 文档渲染年 / 2500+ 学校承载——和视频的 KPI 带同构。
- **经历**：时间线，每段工作列**技术栈标签胶囊**（Python / LangChain / Kafka / Dubbo3 / K8s…），正文用「— 要点」逐条写。
- **技能**：分类卡片（AI/Agent、AI工作台、架构设计、Java后端、数据架构、多语言），每项技能带**蓝色水平进度条 + 右对齐「核心 / 熟练」等级**——比视频里的纯标签更可视化。
- **项目**：**两列卡片网格**，每张卡片 = 标题（带外链箭头）+ 一句话简介 + 「—」要点列表 + 技术栈标签胶囊 + 一张主题插画。其中一张卡片就是**「本站」自己**，用简历介绍自己的技术栈（自我指涉，用作品证明工程能力）。
- **页底**：直接公开邮箱 / GitHub / 电话 + 隐私政策链接。

### 8.2 它是怎么做的（技术栈，来自项目卡片自述）

- **Next.js 16 全栈 monorepo（pnpm）**：前后端分离部署，后端轻量 DDD 四层分层。
- **简历版本管理系统**：内容**不可变快照 + 发布指针 + 自动归档**，Prisma 7 / PostgreSQL 18——所以页首敢标「在线简历 · v19」，每次改简历都留版本。
- pino 结构化日志（JSONL 按天轮转）、Docker Compose 四服务容器化、Playwright e2e 公网验收 8/8 通过。
- Tailwind 4 做样式。
- 「下载 PDF」是站点能力的一部分（对应我们已有的静默 PDF）。

### 8.3 它最大的亮点：内嵌「AI 简历助手」

- 右下角悬浮「**问 AI · 符合你的 JD 吗？**」按钮，点开是聊天窗：
  - 标题「AI 简历助手 · 在线·可提问」（绿点在线状态）。
  - 欢迎语引导「可以问经历/技能/项目，也可以贴一段 JD，让我评估匹配度」。
  - 三个建议问题快捷入口（「他符合 XX 岗位要求吗」「介绍他的 XX 经验」）。
  - 实测：问「他符合 AI 应用工程师岗位要求吗」，它**不硬答**，而是反问「方便把 JD 原文贴给我吗」并给出三个分支（贴 JD / 按岗位名粗略评 / 关心学历年限硬门槛）——是**有状态的多轮 RAG**，不是关键词回复。
  - 底部固定免责：「AI 助手基于公开简历回答，仅供参考」。
- 这是视频里没有的能力：**把简历本身变成一个可对话的接口**——HR/业务面试官不用读完所有文字，直接贴 JD 问匹配度。

#### 8.3.1 隐藏价值：访客提问本身就是作者的面试情报

> 2026-09-19 补充（来自用户观察）。这个「问 AI」入口有**双向价值**，不只是给访客的工具：

- 表面上：访客（HR / 业务面试官 / 感兴趣的人）贴 JD 或提问，AI 基于公开简历回答。
- 实际上：**所有提问都经过它的后端（Next.js + PostgreSQL）并被留存**。对作者而言，这些问题本身就是情报——
  - **知道别人对自己最好奇什么**：哪些经历被反复追问、哪个项目被当作重点、哪些点总被质疑（比如学历、年限、技术深度），正好用来反推面试官真实关注点。
  - **前置面试准备**：不用等真面试结束才复盘，访客在正式面试前就已经替你"预演"了高频问题；作者可以据此补官网内容、打磨话术。
  - **高频问题 TOP N**：积累一段时间后做个简单统计，就知道自己简历的"疑问点 / 亮点"分布。
- 换句话说，这个 AI 助手既是**给访客的 FAQ**，也是作者的**被动需求调研面板**——比自己"猜面试官会问什么"准得多。

**但这条有三个硬约束，必须一起写清楚：**
1. **需要后端**：会话留存与统计必然要数据库，和本项目「零后端、纯静态导出」路线冲突——和 8.3 的 AI 问答本身一样，只记为**在线部署版**的远期能力，本地静态版不做。
2. **隐私合规**：收集访客提问必须**明示**（该站页底就有「隐私政策」链接，正是为此），不能偷偷把 HR 的提问攒着不告知；至少在聊天窗底部或页脚注明「对话用于改进简历内容」。
3. **数据归属**：问题记录只属于作者本人，不对外展示、不二次分发；统计时做匿名化。

> 对本项目：本地版仍坚持「不收集访客任何数据」；这个"问题收集 → 面试准备"的闭环，作为未来在线版 AI 简历助手的**配套价值**记录在案，和 AI 问答一起延后。

### 8.4 对本项目的判断（什么学、什么不学）

| 它的做法 | 我们怎么办 |
|---|---|
| Next.js + PostgreSQL + 版本快照的**全栈后端** | **不学架构**。本项目坚持本地优先、零后端、单文件导出。版本管理用现有「内容 JSON 导入/导出」+ 飞书历史版本兜底即可，不为这个上数据库。 |
| 深色科技风主题 | **学**：作为官网主题的第二个候选（除新粗野主义外，多一个「深色开发者风」）。主题变量化后，换肤就是换一套 CSS 变量。 |
| 技能**进度条 + 核心/熟练**等级 | **学**：`kpi-band` 之外，技能板块支持「等级 + 可视化条」，比纯标签更直观；PDF 视图退化为「核心/熟练」文字。 |
| 项目卡片**两列网格 + 技术标签胶囊 + 主题插画** | **学**：正是我们 `project-cards` 要的样子；插画用用户上传图或占位，不强制 AI 生成。 |
| 「把本站作为一个项目卡片自我展示」 | **学思路**：官网里可加一个「关于本站/本工具」卡片，用技术栈证明能力（尤其对做工具/平台的人）。 |
| 章节进度小圆点、固定顶栏、版本号「v19」 | **学**：轻量纯前端即可实现，不依赖后端。 |
| 内嵌 **AI 简历助手（贴 JD 问匹配度）** | **记录为远期上限，不列入本期**。它需要后端向量库 + LLM 调用，和「零后端」路线冲突。等 [AI辅助写简历-技术设计方案.md](./AI辅助写简历-技术设计方案.md) 的本地转发层落地后，可作为「在线部署版」的增强项，而非本地工具的默认能力。 |
| 页底直接公开真实手机号 | **不学**。我们坚持「公开前脱敏」默认关手机号/住址；这个站作者选择公开是他个人的决定，不应成为工具默认。 |

> **一句话**：这个站证明了「个人求职官网」可以做到全栈+AI问答的高度，但它走的是「在线产品」路线；
> 我们的「官网导出」是「本地简历数据的第五种渲染」，**视觉和信息架构照它学（深色主题、技能进度条、项目卡片网格、章节导航），架构和 AI 问答只记为远期方向**。

## 九、域名、托管与流量（部署侧调研）

### 9.1 resume.nodetime.top 的域名定性（已实测）

- **不是公共平台送的二级域名**，是作者**自购的独立域名 + 自有服务器**：
  - `resume.nodetime.top` 是 `nodetime.top`（`.top` 顶级域，作者自行注册）下的子域名，不是 `*.github.io` / `*.vercel.app` / `*.netlify.app` / `*.pages.dev` 这类平台分配名。
  - 实测解析到 **8.218.79.152（阿里云 IP 段）**，响应头 `server: nginx/1.27.5`、`x-powered-by: Next.js`——nginx 反代一个自建 Next.js 全栈服务，和它自述的「Docker Compose 四服务容器化」一致。
- 结论：它是**私人买域名 + 云服务器自托管**，成本和运维门槛都不低。对我们「导出一个静态 HTML 文件」的目标来说，**这条路过重，不推荐照搬**。

### 9.3 流量真相：公共免费域名本身不导流

**先把期望摆正**：`github.io` / `vercel.app` 这类公共免费域名**不会因为你用了它就给你曝光**——平台不分发、不推荐、不导流。个人简历站不是内容产品，「挂上去就有人看」是错觉。

流量实际只来自三个渠道：

1. **主动递链接（占 90%）**：在 PDF 简历、BOSS/猎聘等招聘沟通、GitHub README、邮件签名、社交主页里放这个网址。小红书视频演示的就是这一幕——发完 PDF 补一句「这是我的个人网站，您看看：<链接>」。**这才是个人简历站的真实使用方式**。
2. **搜索引擎收录**：把 `<title>` 和正文写成「真实姓名 + 岗位」，Google/Bing 能收录；别人搜你名字时命中。自定义姓名域名 + 规范 title 效果最好，`github.io` 也能收录但权重挂在 GitHub 下["https://climbtheladder.com/how-to-make-a-resume-website-step-by-step/","https://scholardue.com/en/blog/setting-up-academic-website"]。
3. **社区外链**：分享到掘金/V2EX/即刻/Hacker News，带来外链，并被各类 AI 爬虫抓取（这反而会让「AI 简历助手」类工具在被问起你时引用到你）["https://zywkloo.github.io/docs/blog-marketing/"]。

**公共平台相对「自建域名+VPS」的真实优势，不是流量，而是**：
- 零运维、不宕机、全球 CDN 快、自带 HTTPS；
- GitHub Pages / Vercel 在技术圈有**可信度背书**（面试官看到 `xxx.github.io` 知道你会用 Git）；
- 免费二级域名 0 成本即可验证「到底有没有人点」。

### 9.4 给本项目的推荐路径

结合本项目「导出一个静态单文件 HTML」的形态，部署侧不需要教用户买服务器，工具内置这套指引即可：

1. **零成本起步**：导出 HTML → 拖到 Vercel / Netlify，或推到 GitHub 仓库开 Pages → 拿到 `xxx.vercel.app` / `xxx.github.io` 链接。
2. **想要更像自己的**：申请 `名字.is-a.dev` 或 `名字.us.kg`，CNAME 到上面的托管。
3. **长期品牌**：花 ~$10/年买 `姓名.com/.dev`，绑到同一个托管（所有平台都支持自定义域名+免费 HTTPS，不丢链接）。
4. **工具要做的事**：导出官网后，弹一段**部署三步走 + 可复制话术**（对应 5.1 的「附言模板」），并提醒：流量靠你自己在简历/招聘软件里递链接，平台不保证曝光；公开前再过一遍脱敏开关。
5. **不做**：不替用户注册域名、不内置服务器/数据库、不做访问统计（坚持零后端、不收集访客数据）。

## 十、一句话结论

> 视频演示的「AI 把简历变成一个漂亮的个人官网」是个好产物形态，但**核心不在 AI，在「同一份结构化数据多一种渲染」**。
> 本项目已经有结构化简历数据、单文件导出和静默 PDF，缺的只是一个**官网主题 + 两种卡片板块 + 脱敏开关 + 一段招聘软件附言**。
> 真正值得抄的是它背后的**技能协议**：输入体检、缺口澄清、数据交叉校验、生成前对齐、修改后回归。
> 做的时候守住三条：**官网不替代 PDF、公开前默认脱敏、数字和公司名永远来自用户已录入数据。**
