## 二、可借鉴点的逐条映射（抄什么 → 落到本项目变成什么）

> 原则：**只抄思想与数据模型，不抄框架与部署栈**。本项目已明确"不上 React/Vue/Vite、守 file:// 直开 + 单文件离线版"，三家全是框架型，所以技术栈层面一律不学。

### 借鉴点 1：结构化样式规则（来自 Reactive Resume）→ 本项目「排版引擎」

**Reactive Resume 做对了什么**：把"字号/间距/颜色/板块顺序"抽象成一套**结构化的、可序列化的样式规则对象**，而非写死在渲染代码里。这使它能量产 15 套模板、支持实时切换、并且 JSON Resume 导出时天然带样式。

**本项目现状**：排版引擎优秀（`resume-render.js`），但样式配置散在 `data.js` 的常量与多处内联里，模板切换（`#/templates`）是空壳。

**落地改造项（编号 A1）**：

| 项 | 内容 |
|---|---|
| 目标 | 把「字号、行距、段距、页边距、配色、板块显隐/顺序」收敛成一份**主题描述对象**（Theme Schema），渲染层只消费它 |
| 落地 | 新建 `js/theme.js`（或扩展现有 theme 模块）：`{ fonts:{name,size,lineHeight}, spacing:{...}, color:{primary,ink,paper}, sections:{order:[...], visible:{...}} }`；`resume-render.js` 从"读常量"改为"读当前 theme 对象" |
| 收益 | ① 模板从"空壳"变成"theme 切换"即可落地；② 为"一岗一简历"的版式定制打底；③ 未来 AI 可生成/推荐 theme |
| 验收 | 切一份 theme → 预览字号/间距/配色同步变化；导出 JSON 能带回 theme；`#/templates` 从空壳变成可选模板列表 |
| 优先级 | P1（2–3 天），但**可延后**——当前自定义能力已够用，属"锦上添花" |

### 借鉴点 2：JSON Resume 生态兼容（来自 Reactive Resume + jsonresume）→ 本项目「互操作」

**做对了什么**：Reactive Resume 以 JSON Resume（`basics/work/education/skills/...`）为数据底座，导入导出无缝。jsonresume/resume-cli 是事实标准。

**本项目现状**：数据模型是自有的 `template.json` 结构，与 JSON Resume 不互通。用户换工具 / 接第三方服务会有迁移成本。

**落地改造项（编号 A2）**：

| 项 | 内容 |
|---|---|
| 目标 | 增加"导入/导出 JSON Resume"两个适配器，不改变内部模型 |
| 落地 | 新建 `js/io/jsonresume-adapter.js`：`fromJsonResume(obj)` 做字段映射（basics→基本信息、work→工作经历、education→教育、skills→技能、projects/languages/interests→自定义板块），`toJsonResume()` 反向；在导入/导出入口各挂一个选项 |
| 收益 | ① 接入 JSON Resume 生态（未来可用其开源模板渲染、对接第三方 ATS）；② 用户可自由迁出，符合"数据可移植"的产品原则 |
| 验收 | 一份 JSON Resume 样例导入 → 预览字段完整；本项目简历导出 JSON Resume → 用 `resume-cli` 能正常渲染 |
| 优先级 | P2（1–2 天），低风险、纯增量，**建议早做**（成本低、锁死可移植性） |

### 借鉴点 3：Resume Parser 结构化解析（来自 OpenResume，最高价值）→ 本项目「导入升级」

**OpenResume 做对了什么**：用 PDF.js 解析已有简历 PDF，**识别出结构化字段**（姓名、联系方式、各段经历、技能、教育），而不是只存原文。这是它"把已有简历一键变可编辑"的核心竞争力，也是它 ATS 友好的来源。

**本项目现状**：`tools/pdf-parse.js` 已落地 PDF 解析，但只做"识别姓名+联系方式 + 原文全保留进『导入原文』"，**不臆造结构**——方向保守、正确，但天花板就是"半自动"。

**落地改造项（编号 A3，本次最高价值）**：

| 项 | 内容 |
|---|---|
| 目标 | 在"原文全保留"之上，增加**可选的结构化预填充**：解析出的工作经历/教育/技能，先填入结构化字段，用户一键确认或微调，原文仍保留兜底 |
| 落地 | ① 服务端 `tools/pdf-parse.js` 增加字段级抽取（姓名、电话、邮箱、公司+时间段、学校+学位、技能关键词），仍"低置信度不硬猜、标注待确认"；② 前端导入流程加"解析预览 + 一键套用/逐项确认"步骤；③ 继续坚持"不臆造"原则——存疑字段标记黄色，绝不静默填错 |
| 收益 | 把"导入一份 PDF"从"重新手打"变成"半自动"，是**用户换工具迁移成本的最低点**，也是本项目目前唯一明显落后于 OpenResume 的能力 |
| 验收 | 用真实简历 PDF 导入 → 工作经历/教育/技能自动预填 ≥70% 字段；存疑项被标记而非静默填入；原文仍完整可查 |
| 优先级 | **P1（最高，3–5 天）** |

### 借鉴点 4：AI harness / JD 驱动一岗一简历（来自 Resume Matcher，方向印证）→ 本项目「主线 A 的第 3 步」

**Resume Matcher 做对了什么**：从"规则打分"转型为"master resume + 贴 JD → AI 生成定制版 + 求职信 → 导出 PDF"，支持本地 LLM。这是它 28.5k star 的原因——**它卖的是"帮我写"，不是"帮我排"**。

**本项目现状**：`js/jd-match.js` 已落地"粘贴 JD → 已覆盖/弱覆盖/缺失清单 + 命中板块"（纯规则），但"生成针对该 JD 的派生版本"（主线 A 第 3 步）尚未做。`docs/产品评估与演进建议.md` 已明确这是最高价值跃迁点。

**落地改造项（编号 A4）**：

| 项 | 内容 |
|---|---|
| 目标 | 在 JD 匹配之上，产出"针对该 JD 的**派生版本**"（不覆盖主简历） |
| 落地 | ① 复用 `js/store/resume-store.js` 的"一简历一文档"模型，派生版本 = 新 id + `parentId` 指向主简历；② 规则版：把"缺失关键词"按命中板块**建议填充位置**，用户一键生成候选句（复用 STAR 素材库，见 A5）；③ AI 版（Key 到位后）：接 `tools/ai-proxy.js`，走"生成 → Diff 审阅 → 应用 → 撤销"闭环 |
| 收益 | 这是**产品定位从"编辑器"转向"内容生产"的决定性一步**，直接对应工作区目录名"简历定制优化"的真实意图 |
| 验收 | 粘贴一份 JD → 生成一份派生简历（不覆盖主简历），可对照"缺失关键词已补/弱覆盖已强化"；投递后可回溯到主简历 |
| 优先级 | **P1（最高，1 周）**，规则版先行，AI 版等 Key |

### 借鉴点 5：经历素材库 / STAR 片段复用（来自 Resume Matcher 的 master resume 思想）→ 本项目「素材库」

**做对了什么**：Resume Matcher 的核心是"一份 master resume 打底，针对不同岗位抽取重组"，而不是每份简历从零写。

**本项目现状**：无素材库概念，每份简历独立维护，重复经历要在多份简历里重复写。

**落地改造项（编号 A5）**：

| 项 | 内容 |
|---|---|
| 目标 | 建"经历素材库"：把一段段 STAR（情境-任务-行动-结果）经历作为可复用片段，投不同岗位时按需勾选组装进简历 |
| 落地 | ① 新增素材库存储（可复用 store 门面的一个分区）；② UI：把已有简历的"工作经历/项目经历"逐条可"存入素材库"；③ 组装：新建/派生简历时可从素材库勾选导入；④ 与 A4 天然结合——JD 匹配命中"缺失技能"时，推荐库里含该技能的 STAR 片段 |
| 收益 | 资深求职者的真实工作流（一段经历投多个岗位要改写侧重点），也是 A4 的内容弹药 |
| 验收 | 一条经历存入素材库 → 在另一份简历中一键导入；JD 匹配时能推荐相关素材片段 |
| 优先级 | P2（1 周），A4 的配套项，可与 A4 合并排期 |

### 借鉴点 6：分享链接 / 在线预览（三家都有，本项目空白）→ 本项目「分享能力」

**做对了什么**：Reactive Resume 有分享链接、可自托管；OpenResume 生成可分享的在线简历；连中文项目猫步简历都有超清 PDF + 在线预览。**"简历做完得能发给别人看"是刚需**。

**本项目现状**：`docs/个人求职官网导出-技术设计方案.md` 已有完整设计（`tools/render-resume.js` 出只读静态页），但尚未落地分享能力。评估文档已把"只读分享/批注"列为 P2 #14。

**落地改造项（编号 A6）**：

| 项 | 内容 |
|---|---|
| 目标 | 一键导出"只读分享页"（静态 HTML，可本地打开或后续上飞书/静态托管），对方无需注册即可查看 |
| 落地 | 复用 `tools/render-resume.js` 出只读静态页；导出入口加"分享页"选项；可选批注（飞书文档评论 / 导出可批注 HTML） |
| 收益 | 补上"简历做完发不出去"的短板；且**无需服务端**——静态 HTML 可放任意静态托管，守住"不做账号体系"的决策 |
| 验收 | 点"导出分享页" → 得到一个可独立打开的只读 HTML，内容与主简历一致、不含编辑控件、可加"仅查看"水印 |
| 优先级 | P2（2–3 天），与 A2 同属"低成本补齐产品闭环" |

### 借鉴点 7：AI 多模型直连（来自 magic-resume）→ 本项目「AI 阶段 2 的模型选择」

**做对了什么**：magic-resume 中文团队，支持 DeepSeek/Qwen/豆包**直连**，说明中文简历场景对国产模型亲和。

**本项目现状**：`docs/AI辅助写简历-技术设计方案.md` 已定 DeepSeek v4 + `tools/ai-proxy.js` 中转（LLM 禁浏览器直连，CORS）。评估文档已把 AI 阶段 2 列为 P2 #11。

**落地改造项（编号 A7）**：

| 项 | 内容 |
|---|---|
| 目标 | AI 阶段 2 核心闭环落地：选中 → 润色 → Diff 审阅 → 应用 → 撤销 |
| 落地 | 按已定设计：`js/ai/scope.js`（作用范围显式）+ `prompts.js` + `diff.js` + `apply.js` + Diff 卡片 UI；模型走 `tools/ai-proxy.js`；Key 存 gitignored `ai.config.json` |
| 收益 | 把评估文档"痛点 1（我该写什么怎么写）"变成功能；这是**付费意愿最强**的一环 |
| 验收 | 选中一段经历 → 点润色 → 出 Diff 对比 → 应用或撤销；事实护栏拦截编造的数字/公司名；可脱敏再发送 |
| 优先级 | **P2（Key 到位后立即做，3–5 天）** |

## 三、落地排期（建议顺序，30 天）

> 原则：**先抄"补短板、锁可移植性"的低成本项，再做"内容生产"的高价值项，AI 等 Key。**

| 周 | 落地项 | 借鉴来源 | 验收一句话 |
|---|---|---|---|
| 第 1 周 | **A3 结构化解析**（最高价值）+ **A2 JSON Resume 适配** | OpenResume / jsonresume | PDF 导入 ≥70% 字段自动预填且不臆造；JSON Resume 双向互通 |
| 第 2 周 | **A4 JD 派生版本（规则版）+ A5 素材库** | Resume Matcher | 一份 JD → 一份不覆盖主简历的派生版，缺失关键词已补位 |
| 第 3 周 | **A6 分享页** + **A1 主题 Schema（可选）** | Reactive Resume / 三家共性 | 一键出只读分享页；theme 切换生效 |
| 第 4 周 | **A7 AI 阶段 2**（Key 到位后） | magic-resume / Reactive Resume | 跑通"润色 → Diff → 应用 → 撤销"闭环 |

**明确不做**（延续评估文档 §九，防止被开源项目带偏）：

1. **不引入 React/Vue/NestJS/Next.js 框架**——三家全是框架型，但本项目"原生 JS + file:// 直开 + 单文件离线版"是护城河，架构层面一律不抄。
2. **不做服务端账号体系 / 不自托管后端**——Reactive Resume 的 NestJS 自托管栈不学；分享靠静态 HTML 即可。
3. **不学 RenderCV 的 CLI/Python 路线**——面向学术、无可视化编辑器，方向不同。
4. **不在 AI 之前继续加导出格式或新平台**——导出已有 6 种、平台 4 个，边际收益已很低。

## 四、落地时的工程护栏（承接项目铁律，防倒退）

> 每做一个改造项，都必须遵守项目既有的硬约定（详见 `.workbuddy/memory/MEMORY.md`），这里只列与本方案直接相关的：

1. **新增前端模块必改四处**：① `index.html` `<script>`（顺序 store < ui < app.js）；② `tools/build-single.js` 白名单；③ `test/run.js` vm 同序加载并接进报告链；④ 重建 `dist/` 与 `dist-desktop/`。拆全局模块时**第五处**必改 `tools/render-resume.js` 的 vm 沙箱。
2. **断言落"失效面"**：写完跑**变异测试**（改坏一行 → 断言必须红 → 还原），否则"全绿"可能是没测到。
3. **A3 解析不臆造**：结构化预填充必须"低置信度标黄待确认、绝不静默填错"，原文永远全保留——守住既有 `tools/pdf-parse.js` 的"不臆造结构"铁律。
4. **PII 隔离**：新增的素材库、派生版本、分享页导出，提交前 `git grep` 扫 PII（真实姓名/公司名等），测试数据一律虚构名。
5. **A7 AI 五原则**：Diff 审阅 / 范围显式 / 可撤销（进撤销栈）/ guard 护栏（拦截编造数字与公司名）/ 可脱敏——`docs/AI辅助写简历-技术设计方案.md` 已定，AI 改造不得绕过。
6. **数据写盘走 `currentPayload()` + savedAt**：A4 派生版本、A5 素材库新增的持久化，一律复用 store 门面，禁止在 saveState/pushRepo 处自拼对象。

## 五、总结
