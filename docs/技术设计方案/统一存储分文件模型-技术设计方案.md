## 1. 结论（TL;DR）

项目存储从「浏览器持久化 + 单文件 `data/resume.json`」整体改造为「**分文件**」模型：

**一份简历 = 一个文档（docId = resumeId）**，本地保存与飞书同步保存同构，业务代码只面向「文档」读写。



| # | 需求                          | 结论                                                                        |
| - | --------------------------- | ------------------------------------------------------------------------- |
| ① | 打包安装后无浏览器环境，浏览器持久化是否还需要     | **已移除**：IndexedDB 与 localStorage 不再承载简历数据，仅保留 UI 偏好                       |
| ② | 本地多份简历分文件结构，与飞书上报的多文件结构是否一致 | **已统一同构**：`resumes/<id>.json` ↔ 飞书 `file_token_<id>` / `document_id_<id>` |
| ③ | 安装包本地保存路径是否在安装包目录           | **不在**：用系统用户数据目录 `app_data_dir()`（用户已确认）                                  |
| ④ | 本地自动保存是否先内容哈希比对             | **是**：`stableHash` 指纹比对后才写盘，未变跳过                                          |
| ⑤ | 系统配置数据与简历数据是否分文件            | **是**：`resumes/` 与 `sync.config.json` / `sync.state.json` 彻底分离，本地与飞书一致    |
| ⑥ | 分文件命名规则；重命名简历是否影响真实数据文件     | **文件名 = 简历 id（稳定锚点）**；重命名只改索引 `title`，正文文件不动                              |
| ⑦ | 存储是否抽象封装                    | **是**：`ResumeLibrary` 后端可注入（native /http/memory），未来数据源实现同一契约即可            |

## 2. 背景：改造前的存储链路与问题

### 2.1 旧链路（改造前）



```
编辑操作 → saveState()

&#x20; ├─ localStorage（resume\_builder\_data\_v1）        ← 浏览器唯一落点（离线兜底）

&#x20; ├─ IndexedDB（resume\_builder / resume\_library）  ← 多简历库

&#x20; └─ POST /api/resume → data/resume.json           ← 单文件实时写回（web 模式）

飞书同步（可选）：docx 双写 + 云盘文件，file\_token\_\<id> / document\_id\_\<id> 按 id 分键

自动同步：60s/轮，stableHash(djb2) 去重
```

### 2.2 问题清单（对应 7 点诉求）



| # | 问题                               | 影响                                           |
| - | -------------------------------- | -------------------------------------------- |
| ① | IndexedDB /localStorage 依赖浏览器运行时 | 打包安装包后**无浏览器环境**，这条持久化路径是死依赖                 |
| ② | 本地是「单文件」、飞书是「多文件按 id 分键」         | 两种形态结构不一致，双写 / 迁移要写兼容层                       |
| ③ | 安装包数据路径未明确                       | 用户误以为数据在安装包目录（该目录常只读、升级 / 卸载会清空）             |
| ④ | 本地保存无指纹比对                        | 每次防抖都写盘，内容未变也产生写 IO；飞书侧已有 stableHash 去重，本地缺失 |
| ⑤ | 配置（sync.config.json 等）与简历数据同数据流  | 凭证与正文耦合，权限 / 备份 / 同步边界不清                     |
| ⑥ | 单文件模型下「重命名」无独立文件概念               | 多文件化后必须定命名规则，否则标题变文件名会带来特殊字符 / 重名 / 长度问题     |
| ⑦ | 浏览器 / 本地服务 / 原生层三套读写散落           | 新数据源（如远端云盘）需要各自兼容层                           |

## 3. 设计目标与原则



1. **一份简历 = 一个文档**：`docId = resumeId`，本地与飞书两侧同构，无兼容层。

2. **索引与正文分离**：`index.json`（清单 + 元数据，小、常读）与 `<id>.json`（正文，大、按需加载）。

3. **配置与简历分文件**：凭证 / 同步状态独立于简历正文，两侧一致。

4. **统一抽象、后端可注入**：业务代码只面向「文档读写」契约，不感知具体后端。

5. **哈希比对防无意义写盘**：本地与飞书共用同一套 `stableHash` 指纹。

6. **文件名 = 稳定锚点**：文件名是简历 id 而非标题，重命名 / 打标签不触碰正文文件。



***

## 4. 统一分文件模型（核心）

### 4.1 两级结构



```
resumes/

├── index.json   # 简历清单 + 激活态 + 内容指纹 + 同步进度

└── \<id>.json    # 每份简历一个文件：{data, fonts, spacing, v, savedAt}
```

### 4.2 `index.json` 结构



```
{

&#x20; "active": "res\_xxx",                 // 激活简历 id

&#x20; "items": \[

&#x20;   {

&#x20;     "id": "res\_xxx",                 // 稳定锚点，即文件名 / 飞书分键

&#x20;     "title": "林一帆 · Agent 岗",     // 展示名（重命名只改这里）

&#x20;     "source": "local",               // 来源：local / feishu / ...

&#x20;     "docId": "res\_xxx",              // 文档标识（= id）

&#x20;     "updatedAt": 1758...,            // 毫秒时间戳

&#x20;     "tags": \[],                      // 标签（同样只改索引）

&#x20;     "lastHash": "…",                 // 最近一次写盘指纹（本地自动保存比对用）

&#x20;     "lastPushedHash": "…",           // 最近一次成功上报飞书的指纹

&#x20;     "lastRemoteFp": "…",             // 远端指纹（防重复拉取）

&#x20;     "skipNextPull": false,           // 跳过下一轮拉取（刚推完避免回环）

&#x20;     "lastPushNotifyAt": 0            // 最近一次推送通知时间（节流）

&#x20;   }

&#x20; ]

}
```

### 4.3 本地与飞书同构对照



| 语义        | 本地（web / 桌面）                       | 飞书                                                  |
| --------- | ---------------------------------- | --------------------------------------------------- |
| 清单        | `resumes/index.json`               | 本地索引（按 id 分键的 token 表在 `sync.state.json`）           |
| 简历正文      | `resumes/<id>.json`                | 云盘文件 `file_token_<id>` + docx 文档 `document_id_<id>` |
| 版本历史      | 文件系统（版本化工具可选）                      | 飞书云盘版本历史                                            |
| 重命名 / 打标签 | 只改 `index.json` 的 `title` / `tags` | 文档标题（不动 token 键）                                    |

**为什么用 id 做键而非标题**：标题会变（用户重命名）、会重名、含特殊字符、长度不可控；

id 一旦生成终身不变，本地文件名与飞书分键共享同一稳定锚点。

## 5. 存储抽象层

### 5.1 统一契约

`ResumeLibrary`（`js/store/resume-library.js`）只依赖以下接口，任何后端实现它即可接入：



| 接口                  | 语义                  |
| ------------------- | ------------------- |
| `listIndex()`       | 读索引清单（`index.json`） |
| `writeIndex(index)` | 写索引清单（带结构校验）        |
| `loadDoc(id)`       | 读单份简历文档（不存在返回 null） |
| `saveDoc(id, doc)`  | 写单份简历文档             |
| `removeDoc(id)`     | 删除单份简历文档            |

### 5.2 三后端与自动检测



```
detectBackend()  // 优先级：native（Tauri 注入）→ http（fetch 可用）→ memory（兜底降级）

setBackend(b)    // native-bridge 注入时显式指定
```



| 后端     | 实现                                          | 适用                       |
| ------ | ------------------------------------------- | ------------------------ |
| native | `invoke('resume_index_*' / 'resume_doc_*')` | 桌面 / Android 安装包（无浏览器环境） |
| http   | `fetch('/api/library/*')`                   | web 开发模式（`npm start`）    |
| memory | Map 内存                                      | 单文件版 / 无写服务时的降级          |

### 5.3 门面不变

`ResumeStore`（`js/store/resume-store.js`）对外接口不变：`LocalStore` 的 `get/set`

重定向为「default 文档」的读写，业务代码（`js/app.js` 等）零改动平滑过渡。

### 5.4 未来数据源接入

新增远端数据源（如通用云盘）时，只需实现上述 5 个接口并注册后端，

「多份简历」「激活态」「指纹去重」「同步进度」全部复用，不需要兼容层。

## 6. 本地实现

### 6.1 桌面 / Android：`src-tauri/src/storage.rs`（新增）

5 个 `#[tauri::command]`，与 serve.js 的 `/api/library/*` 同构：



| 命令                  | 语义                       |
| ------------------- | ------------------------ |
| `resume_index_load` | 读 `resumes/index.json`   |
| `resume_index_save` | 写索引（结构校验 + 原子 pretty 写入） |
| `resume_doc_load`   | 读 `resumes/<id>.json`    |
| `resume_doc_save`   | 写文档（原子写入）                |
| `resume_doc_remove` | 删文档 + 清理索引项              |

关键实现点：



* `resumes_dir()`：目录不存在时自动创建；

* `write_json`：临时文件 + 原子替换，避免写一半损坏；

* `sanitize_id`：`^[A-Za-z0-9_-]{1,128}$` 校验，拒绝路径穿越。

`src-tauri/src/lib.rs` 追加 `mod storage;` 并在 `generate_handler!` 注册 5 个命令。

### 6.2 web 开发模式：`tools/serve.js`

新增 `/api/library/*`（与桌面端命令同构）：



| 接口                                | 语义                          |
| --------------------------------- | --------------------------- |
| `GET /api/library/index`          | 读 `data/resumes/index.json` |
| `POST /api/library/index`         | 写索引（结构校验）                   |
| `GET /api/library/doc?id=<id>`    | 读文档                         |
| `POST /api/library/doc`           | 写文档（body 需含 `data`）         |
| `DELETE /api/library/doc?id=<id>` | 删文档                         |

旧 `/api/resume`（单文件写回）保留兼容；非法 id（如 `id=../package.json`）返回 `{"error":"非法简历 id"}`。

### 6.3 路径：系统用户数据目录（非安装包目录）

**决策**：数据放 Tauri `app.app_data_dir()`，**不放安装包目录**（用户已确认）。



| 平台      | 简历数据路径                                                            |
| ------- | ----------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/com.resumestudio.desktop/resumes/` |
| Windows | `%APPDATA%\com.resumestudio.desktop\resumes\`                     |
| Linux   | `~/.local/share/com.resumestudio.desktop/resumes/`                |
| web 开发  | `data/resumes/`（项目内，gitignored）                                   |

理由：安装目录通常只读（Program Files //usr 等），且升级、卸载会被清空；

系统用户数据目录是各平台约定俗成的「应用私有数据」位置，卸载后数据默认保留。

### 6.4 配置类路径

系统配置（凭证 / 同步状态）走 `app.app_config_dir()`（`config.rs` 既有逻辑）：



| 文件                 | 内容                                                               | 归属                          |
| ------------------ | ---------------------------------------------------------------- | --------------------------- |
| `sync.config.json` | 飞书应用凭证 / 文件夹配置                                                   | 系统配置（gitignored，绝不上库、不进浏览器） |
| `sync.state.json`  | 飞书 token（`file_token_<id>` / `document_id_<id>`，按简历 id + 认证身份分键） | 同步状态                        |
| `sync.oauth.json`  | 扫码授权凭证                                                           | 系统配置（gitignored）            |

web 模式下同名单文件由 serve.js 在项目根目录读写，静态服务一律 403 拒绝下发。

## 7. 自动保存：哈希比对 + 防抖

本地自动保存与飞书自动同步共用**同一套指纹** `stableHash`（key 排序后 djb2，`js/feishu/feishu-sync.js`）：



```
编辑操作 → saveState()

&#x20; ├─ 计算 stableHash(payload)

&#x20; ├─ 多份模式：与 index.json 持久化的 lastHash 比对（重启后仍生效）

&#x20; │    ├─ hash === lastHash → 内容未变，直接 return（不写盘）

&#x20; │    └─ 变化 → 800ms 防抖后写盘 + 更新 lastHash

&#x20; └─ 单份模式：与内存 \_defaultLastHash 比对，同样未变跳过
```

指纹持久化在 `index.json` 的 `lastHash`，因此：



* 重启后再次打开，无修改则完全跳过写盘；

* 多份简历各自独立比对，互不干扰；

* 与飞书自动同步的 `lastPushedHash` 语义一致，两侧去重规则统一。



***

## 8. 文件名与 id 规则 / 重命名语义

### 8.1 id 生成与校验



```
genId() → 'res\_' + Date.now().toString(36) + 随机后缀   // 例：res\_lx2k3f9a

校验：^\[A-Za-z0-9\_-]{1,128}\$                            // Rust sanitize\_id 与 serve.js 同规则
```



* 校验正则同时用于 Rust 与 serve.js，**路径穿越（**`../`**、**`/`**）一律拒绝**；

* id 不依赖标题，故标题任意变更不影响文件定位。

### 8.2 重命名 / 打标签的语义



```
用户重命名 → ResumeLibrary.rename(id, newTitle)

&#x20; → 只改 index.json 中该条的 title（tags 同理）

&#x20; → 正文文件 \<id>.json 不动（文件名不变）

&#x20; → 飞书侧文档标题同步改，token 键（file\_token\_\<id>）不变
```

**结论**：用户在任何界面重命名简历，真实数据文件（本地 `<id>.json` / 飞书 token 键）都不受影响，

消除了「重命名导致数据文件漂移」的担忧。

## 9. 系统配置与简历数据分文件



| 类别        | 本地落点                                    | 飞书侧                                    |
| --------- | --------------------------------------- | -------------------------------------- |
| 简历正文 + 索引 | `resumes/`（或 `app_data_dir()/resumes/`） | `file_token_<id>` / `document_id_<id>` |
| 系统配置 / 凭证 | `app_config_dir()`（web：项目根）             | 只存本机，**绝不下发到浏览器**                      |
| 同步状态      | `sync.state.json`                       | 本地状态表                                  |

**飞书自动同步进度迁移**：`lastPushedHash` / `lastRemoteFp` / `skipNextPull` / `lastPushNotifyAt`

从旧 localStorage 键（`resume_autosync_v1`，已废弃）迁入 `index.json` 索引项 ——

同步进度随简历走、随索引落盘，重启不丢，与本地 / 飞书两侧结构一致。

## 10. 数据迁移

### 10.1 web 模式：旧单份 → 首份简历

`initResumeLibrary()`（`js/app.js`）在「基底数据链（`loadRepoData` → `loadTemplateData`）完成之后」执行：



* 读索引：**空库** → 用当前已加载的单份数据（旧 `data/resume.json` / `template.json` / 种子）建第一份简历；

* 非空库 → 按 `savedAt` 仲裁「库文档 vs 基底」谁新（`pickResumeSource`），基底较新则回写库。

### 10.2 旧 localStorage 清理

`clearSaved()` 与启动流程保留 `SAVE_KEY` / `SAVE_KEY_LEGACY` 常量仅用于**清理旧版本残留键**，

不再承担数据读写。

### 10.3 桌面安装包

安装包场景无旧浏览器数据可迁；「导入数据」按钮（JSON 导入为新简历）已覆盖「迁移旧版 JSON 备份」场景。

## 12. 决策记录（ADR）



| 决策      | 选项                | 选定                 | 理由                                 |
| ------- | ----------------- | ------------------ | ---------------------------------- |
| 安装包数据路径 | 安装包目录 vs 系统用户数据目录 | **系统用户数据目录**（用户确认） | 安装目录只读、升级 / 卸载清空；用户数据目录跨平台约定、卸载保留  |
| 文件名锚点   | 标题 vs id          | **id**             | 标题可变 / 可重名 / 含特殊字符；id 终身稳定，本地与飞书共用 |
| 浏览器持久化  | 保留 vs 移除          | **移除**（仅留 UI 偏好）   | 安装包无浏览器环境；UI 偏好键（面板 / 主题等）保留不影响    |
| 配置与简历   | 同文件 vs 分文件        | **分文件**            | 凭证 / 同步状态与正文权限、备份、同步边界清晰           |
| 指纹比对    | 仅飞书 vs 两侧统一       | **两侧统一**           | 本地 / 飞书同一套 stableHash，去重规则一致、语义可迁移 |

## 13. 开放事项



1. **多设备同步冲突**：沿用既有 `savedAt` 仲裁（`pickResumeSource`）；更复杂的合并策略留待后续。

2. **其余 localStorage 数据**：通知（notifier）、求职追踪（tracker）、AI 面板偏好等仍为 localStorage

   UI 偏好类数据，未纳入存储抽象；如未来打包端需要，可逐项迁移到 `app_config_dir()`。

3. **飞书侧索引**：当前「简历清单」只存本地（`index.json`），飞书侧按 id 分键；

   若未来需要「换设备看到简历列表」，需在飞书云盘也维护一份索引文档（契约已支持）。
