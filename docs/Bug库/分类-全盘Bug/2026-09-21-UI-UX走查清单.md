## 二、缺陷详情

### UX-01 编辑面板「内容编辑」区默认在视口外，配置面板全部展开置顶 — ✅ 已修复（验收通过，2026-09-21）

- **严重程度**：P3（体验优化项）
- **现象**：
  - 打开任一简历进入编辑器、展开「编辑面板」后，右侧面板**首屏全部为配置面板**：字号配置（px）→ 页面边距（mm）→ 间距配置（px）→ 投递体检 → JD 匹配分析，**五个配置面板默认全部展开**。
  - 真正的内容编辑区（`#editor`：姓名输入、联系方式、板块卡片、条目输入）位于滚动区下方，**默认在视口外**（实测 `#editor` 顶部 y≈977，视口高 884），用户需向下滚动约一屏才能看到核心编辑入口。
  - 初次使用且无任何配置需求的新用户，打开「编辑面板」后会误以为"只有字号/边距配置，没有内容编辑"。
- **复现步骤**：
  1. 进入任意简历编辑器；
  2. 展开「编辑面板」；
  3. 观察右侧面板：首屏是「字号配置 / 页面边距 / 间距配置」等全部展开的配置面板；「内容编辑」区块需向下滚动才可见。
- **根因分析**：`.editor-pane` 内 DOM 顺序为「配置面板（`#settings`）→ 内容编辑（`#editor`）」，且配置面板默认展开（`resume_collapsed_panels_v1` 中字号/边距/间距/体检均为展开态）；内容编辑面板虽为 `panel-grow`，但被上方展开的配置面板推出视口。
- **影响范围**：所有用户在平板/窄屏宽度下首次使用编辑器的认知与操作路径；高频操作（改姓名/内容）需要额外滚动。
- **建议修复**：
  - 方案 A：把「内容编辑」面板移到配置面板**之前**（编辑面板打开即见内容）；
  - 方案 B：配置面板默认折叠（字号/边距/间距/体检收成标题行），用户按需展开。
- **回归验证建议**：打开编辑器 → 展开编辑面板 → `#editor` 首屏可见（`getBoundingClientRect().top < 视口高`）。
- **修复落地（2026-09-21）**：采用方案 B——配置面板（字号/边距/间距）默认折叠。改动：`index.html` 三个面板加 `collapsed` 类；`js/app.js` 新增 `DEFAULT_PANEL_STATE` 合并进 `panelCollapsed`（既有用户显式展开过的状态仍保留）。内容编辑面板（`#editor`，`panel-grow`）首屏即见。

### UX-02 键盘焦点可见性不足：全局仅 4 条 `:focus` 样式，普通按钮聚焦无焦点环 — ✅ 已修复（验收通过，2026-09-21）

- **严重程度**：P3（无障碍，WCAG 2.4.7 Focus Visible）
- **现象**：
  - 用键盘 Tab 遍历时，**大部分按钮/标签聚焦后无可见焦点指示**：实测 rail 导航（简历库/编辑器/模板/投递/AI/设置）、「工具菜单」「编辑面板」标签聚焦后 `outline-style: none`，焦点位置不可见。
  - 全项目样式表中 `:focus` / `:focus-visible` 相关规则仅 **4 条**，仅覆盖部分输入框（`.field input:focus`）、save-bar 重试按钮、简历卡片菜单按钮；普通按钮、面板标签、配置项控件均无焦点样式。
- **复现步骤**：
  1. 打开编辑器，连续按 Tab 键遍历；
  2. 观察焦点落在 rail 导航按钮 / 「工具菜单」标签 / 导出按钮时，**没有可见的高亮或轮廓**，无法判断焦点在哪。
- **根因分析**：全局 CSS 未为通用按钮/标签定义 `:focus-visible` 样式（默认 outline 被清除或未声明）；浏览器默认焦点环在部分元素上被 `border:none/outline:none` 移除。
- **影响范围**：键盘用户、辅助技术用户无法定位焦点；与「无障碍优先」的产品定位不符。
- **建议修复**：在 `css/style.css` 补充全局 `button:focus-visible, [tabindex]:focus-visible { outline: 2px solid var(--ui-focus-ring); outline-offset: 1px; }` 一类规则。
- **回归验证建议**：Tab 聚焦任一按钮，视觉上有清晰焦点环。
- **修复落地（2026-09-21）**：`css/style.css` 新增全局 `button:focus-visible, [tabindex]:focus-visible, .panel-header.collapsible:focus-visible{ outline:2px solid var(--ui-focus-ring); outline-offset:1px; }`，覆盖 rail 导航、工具/编辑面板标签、导出等通用按钮（输入框沿用各自 `.field :focus` 样式）。

### UX-03 投递追踪「简历版本」列未关联简历时显示「—」，无任何引导 — ✅ 已修复（验收通过，2026-09-21）

- **严重程度**：P3（体验优化项）
- **现象**：
  - 投递追踪表格「简历版本」列，对未关联简历的记录显示为「—」，用户无法得知该投递使用的哪份简历，也没有入口提示可以关联。
- **复现步骤**：
  1. 进入 `#/tracker`，新建一条不关联简历的投递记录；
  2. 表格「简历版本」列显示「—」，无任何说明或关联入口。
- **根因分析**：表格渲染对空关联直接输出占位符「—」，未提供空值引导（如「未关联 · 点此选择」）。
- **影响范围**：投递记录多时，无法快速辨别记录对应的简历版本，复盘效率低。
- **建议修复**：空值显示「未关联」并提供点击关联简历的入口（或编辑弹窗中突出关联选择）。
- **回归验证建议**：未关联记录显示「未关联」且可点击进入关联流程。
- **修复落地（2026-09-21）**：`js/views/tracker-view.js` 空关联单元格改为可点击按钮「未关联 · 点此关联」（点击即打开该记录编辑弹窗填「关联简历」）；`css/layout.css` 新增 `.tk-link` / `.tk-hint` 样式，并在编辑弹窗「关联简历」下加引导提示。
