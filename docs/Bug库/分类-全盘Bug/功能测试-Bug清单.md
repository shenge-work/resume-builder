## 二、缺陷详情

### BUG-01 「＋ 添加联系方式」按钮点击无任何反应，联系方式无法新增

- **严重程度**：P1
- **现象**：
  - 内容编辑面板 → 「基本信息」区块 → 点击「＋ 添加联系方式」按钮，页面无任何反应（不新增输入行、不跳转、无提示、无报错）。
  - 「还没有联系方式 —— 点下方『＋ 添加联系方式』…」的提示文案永久显示，永远无法消除。
  - 控制台无任何错误输出，属于「静默失败」，用户无法感知是功能缺陷。
- **复现步骤**：
  1. 打开 `http://localhost:8000`，新建一份简历（或使用任意简历）；
  2. 展开「编辑面板」（若收起，点右上角「› 编辑面板」）；
  3. 滚动到「基本信息」区块底部，点击「＋ 添加联系方式」按钮；
  4. 结果：按钮无任何反馈，下方不出现联系方式输入行，提示文案不变。
- **根因分析**（已定位到代码）：
  - `js/render/editor-schema.js`：`BASIC.lists`（含 `id:'contact'` 的联系方式列表，定义于约 428–449 行）**从未被注册进全局 `LIST_INDEX`**。
  - `register()`（约 247–251 行）只对「板块类型 TYPES」的 `def.lists` 调 `indexList`；`BASIC` 是独立定义、仅被 `renderEditorHTML` 直接渲染（约 488 行），没有任何 `register(BASIC)` / `indexList(BASIC)` 调用。
  - 点击链路：`resume-render.js` 的 `handleListAction`（约 412–424 行）→ `ES.checkAction()` → `locate()`（`editor-schema.js` 约 510–519 行）→ 查 `LIST_INDEX['contact']` 得 `undefined` → 返回 `{ok:false}` 且无 `message` → 静默 return false，按钮点击被吞掉。
  - 实证：页面控制台执行 `ResumeEditorSchema.getList('contact')` 返回 `null`；`getList('sections')` 返回正常对象。`checkAction({act:'add',listid:'contact',list:'contact'})` 返回 `{ok:false}`。
  - 该文件自 f1807b3（JD 匹配/菜单收敛/撤销栈重构）引入起即缺此注册，属回归缺陷。
- **建议修复**：在 `editor-schema.js` 模块初始化处对 `BASIC.lists` 逐个 `indexList`（或直接 `register(BASIC)`），使 `contact` 进入 `LIST_INDEX`。
- **回归验证建议**：点击「＋ 添加联系方式」后应新增一行输入框，且 `data.contact.length` 变为 1。

### BUG-02 平板宽度（641–1024px）下右侧配置面板横向溢出、内容被裁切不可见

- **严重程度**：P1
- **现象**：
  - 在 756px 视口（平板档）展开「编辑面板」后，页面出现横向溢出：`document.body.scrollWidth = 837 > 视口 756`。
  - 因 `html, body { overflow:hidden }`（`css/style.css` 204 行），页面**无法横向滚动**，`window.scrollTo(1000,0)` 后 `scrollX` 仍为 0。
  - 右侧配置面板（字号配置、页面边距、间距配置、投递体检、JD 匹配分析）整体位于视口外：面板 `x=756` 起、宽 460，其中输入框（如姓名字号 `x=1134`）完全不可见、不可操作。用户只能看到被裁切的半截内容。
- **复现步骤**：
  1. 浏览器窗口宽度调整为 641–1024px 之间（测试值 756px）；
  2. 打开 `http://localhost:8000`，进入任一简历编辑器；
  3. 展开「编辑面板」；
  4. 结果：右侧「字号配置 / 页面边距 / 间距配置」面板右缘在视口外，内容被裁切，无法横向滚动查看与操作。
- **根因分析**（已定位到代码）：
  - `css/style.css` 212 行：`.editor-pane .panel{min-width:460px;}`（注释「收起动画期间内容不被压缩，仅被 overflow 裁剪」）对**所有宽度**生效。
  - 697–703 行平板媒体查询 `@media (min-width:641px) and (max-width:1024px){ .editor-pane{width:380px;} .side-panel.open{width:380px;} .side-panel-head,.side-panel-body{min-width:380px;} }` 只把容器压到 380px、且只覆盖了**侧栏面板（side-panel）**的 min-width，**漏掉了 `.editor-pane .panel` 的 460px min-width** → 380px 容器塞 460px 面板 → 横向撑破。
  - 结合 204 行 `overflow:hidden`，溢出无法滚动，内容即「不可达」。
  - 实测：`#panel-fonts` 等面板 `getBoundingClientRect().right = 837`；字号输入框 `x=1134`。
- **影响范围**：平板/小屏笔记本（641–1024px）下，字号、页边距、间距、投递体检、JD 匹配等全部配置功能**视觉与操作均不可达**（编辑区文字输入仍可用）。
- **建议修复**：在平板媒体查询内补充 `.editor-pane .panel{min-width:380px;}`（与容器同宽），或把 212 行的 460px 改为不超过容器宽度的值；同时复核 204 行 overflow:hidden 在窄屏下的滚动策略。
- **回归验证建议**：756px 视口下 `document.body.scrollWidth === 756`，字号输入框 `x < 756` 且可点。

### BUG-03 工具菜单 / AI 面板展开时把编辑面板挤出屏幕，收起后不自动恢复

- **严重程度**：P2
- **现象**：
  - 756px 视口下，点击「工具菜单」（或 AI 面板）展开右缘侧栏（宽 380px）后，**编辑面板被推出屏幕**：`.editor-pane` 变成 `x=755, w=1`（1px 宽），其内部全部配置项（字号/间距/体检/JD）不可见、不可操作。
  - 关闭「工具菜单」后，编辑面板**不会自动恢复**，仍保持 1px 折叠态；必须再手动点一次「› 编辑面板」标签才恢复 380px。
  - 折叠态下用户容易误以为「编辑面板丢失 / 页面坏了」。
- **复现步骤**：
  1. 756px 视口下进入编辑器；
  2. 展开「编辑面板」，确认面板正常显示（x≈376，宽 380）；
  3. 点击左缘「‹ 工具菜单」标签展开工具菜单；
  4. 观察：编辑面板被推到屏幕外（x≈756，宽 1px）；
  5. 再点「工具菜单」标签收起侧栏；
  6. 观察：编辑面板仍是 1px，未自动恢复。
- **根因分析**（已定位到代码）：
  - `js/ui/pane-mobile.js` 52–64 行 `setSidePanelOpen()`：展开侧栏时若编辑面板未折叠，则强制 `setPaneCollapsed(true)`（58 行，互斥「多选一」设计）。
  - 70–73 行 document 级点击监听只在点击空白处**收起侧栏**，不会反向恢复编辑面板——「互斥」只做了一半：展开侧栏折叠编辑面板，收起侧栏却不还原。
  - 该交互在窄屏（编辑面板本就拥挤）上问题被放大：工具菜单一开，配置面板整体消失。
- **建议修复**：收起侧栏时若此前编辑面板是被「互斥折叠」的，应自动恢复其展开态；或提供明确的视觉提示（如标签高亮 + 提示「编辑面板已收起」）。
- **回归验证建议**：展开工具菜单 → 编辑面板折叠；收起工具菜单 → 编辑面板自动恢复到 380px。

### BUG-04 每次导出 / 下载后「工具菜单」自动收起，连续导出需反复展开

- **严重程度**：P2
- **现象**：
  - 展开「工具菜单」后点击任一导出（导出纯文本 / Markdown / Word / 单文件 HTML / 分享页 / PDF 等），下载触发后**工具菜单自动关闭**。
  - 连续导出多个格式（如 txt → md → docx）时，每导出一个格式菜单就收起一次，需要反复重新点开「工具菜单」，操作成本高、易误触。
- **复现步骤**：
  1. 展开「工具菜单」；
  2. 点击「导出纯文本（.txt）」，等待下载完成；
  3. 观察：工具菜单已自动收起；
  4. 要导出下一个格式（如 Markdown），必须再次点开「工具菜单」。
- **根因分析**（已定位到代码）：
  - 导出落盘走程序化 `<a download>` 点击（`js/export-extra.js` `saveText`/`saveBytes`，约 378–396 行）：向 `document.body` 临时追加锚点并 `.click()`。
  - 该 click 事件冒泡到 document 级监听（`pane-mobile.js` 70–73 行）：点击目标不在 `.side-panel` 内 → 收起所有打开的侧栏 → 工具菜单被收。
- **建议修复**：下载锚点点击时阻止冒泡（`e.stopPropagation()`），或在 document 监听中排除「由程序化下载触发的点击」。
- **回归验证建议**：连续导出 txt、md、docx 三个格式，菜单始终不收起。

### BUG-05 控制台报错：根路径路由警告 + favicon 404

- **严重程度**：P3
- **现象**：
  - 直接访问根路径 `http://localhost:8000/`（无 hash）时，控制台输出警告 `[router] no route matched: /`。
  - 每次页面加载都会请求 `favicon.ico` 并得到 404（DevTools 网络与 console 各出现 2–4 条 `Failed to load resource: 404` 噪音）。
  - 页面功能不受影响（编辑器内容能正常渲染），但控制台噪音会干扰开发与排障。
- **复现步骤**：
  1. 打开 DevTools（Console / Network）；
  2. 直接访问 `http://localhost:8000/`；
  3. 观察 Console：`[router] no route matched: /`；Network：`/favicon.ico` → 404。
- **根因分析**（已定位到代码）：
  - `js/router/router.js` 38 行解析 hash，115 行对未匹配路径 `console.warn('[router] no route matched:', path)`；路由表未注册根路径 `/`（页面实际内容由其他兜底渲染，属「有兜底但缺显式路由」）。
  - 项目根目录无 `favicon.ico`（`tools/serve.js` 对未命中静态文件统一返回 404，750 行）。
- **建议修复**：为 `/` 注册默认路由（重定向到 `/editor` 或 `/library`）；补充一个 favicon（或空 favicon 占位）消除 404 噪音。
- **回归验证建议**：访问 `/` 无路由警告；`/favicon.ico` 返回 200（或不再被请求）。

### BUG-06 观察项：编辑面板内板块在无任何删除操作时消失（撤销可恢复）

- **严重程度**：P1（数据风险）· **状态：疑似，待复现定位**
- **现象**：
  - 测试过程中，编辑面板里的「个人优势」板块在**两次自动化操作之间（期间没有任何删除按钮点击）**从页面与数据中消失：`data.sections` 从 `[职业履历, 个人优势]` 变为 `[职业履历]`。
  - 该删除被记录为一条**撤销栈 action**（点「撤销」可完整恢复板块）。
  - 之后刻意静置观察 5 秒未再复现；多次尝试复现未果。
- **已观察到的完整时序**（供定位参考）：
  1. 编辑面板内新增「个人优势」板块 → 新增「职业履历」板块（sections = [个人优势, 职业履历]）；
  2. 在**预览区**点击「职业履历」标题行「↑」上移（sections = [职业履历, 个人优势]，此时 getData 实证两板块均在）；
  3. 下一步查询编辑区时，「个人优势」卡片已不在 DOM，数据中 sections = [职业履历]；
  4. 点击「撤销」后板块完整恢复（sections = [职业履历, 个人优势]）。
- **根因分析**：未定位。已排查并排除：预览区 ↑↓ 重排逻辑（`resume-render.js` reorderWithin/moveSection 为纯重排、无删除）；自动保存（内容指纹比对后写盘，无剪枝逻辑）；飞书自动同步（仅对已建立飞书映射的简历生效，测试简历无映射）；重复 id 元素（无）。疑点集中在：多次侧栏互斥折叠/重渲染期间的事件冒泡或竞态，需在固定状态下人工复测。
- **建议处理**：
  - 由开发在以下场景人工复测：连续操作「添加板块 → 预览区上移 → 展开/收起侧栏 → 观察编辑区」；
  - 建议给删除操作（尤其静默删除，见下）增加确认或可感知反馈；
  - **补充说明（已确认）**：当前板块删除为**静默删除、无确认弹窗**（`SECTIONS_LIST` 未配置 `confirm`），若误触「×」会无感知丢失板块——建议至少对板块级删除增加确认。
- **风险提示**：本项为测试期间的单次观察，未稳定复现；在定位到根因前，请勿视为已确认缺陷，但建议优先排查（P1 级数据风险）。
