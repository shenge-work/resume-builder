# Bug 库

本目录用于**归档本项目所有 Bug 记录**，统一管理、按类存放，方便任何人快速定位问题与历史。

## 目录结构

```
docs/Bug库/
├── README.md                    # 本索引：分类规则 + 命名规范 + 归档清单
├── 分类-独立需求Bug/            # 单个需求 / 单个功能模块内的 Bug
│   └── README.md
├── 分类-全盘Bug/                # 跨功能 / 全局性 Bug（布局、路由、数据层、交互、性能、兼容性）
│   ├── 功能测试-Bug清单.md      # 2026-09-21 首轮全功能测试清单（BUG-01 ~ BUG-06）
│   └── 2026-09-21-UI-UX走查清单.md  # 2026-09-21 UI/UX 视角走查（UX-01 ~ UX-03）
├── 分类-每日巡检Bug/            # 日常巡检 / 回归抽查发现的 Bug
│   └── README.md
└── 模板/
    └── Bug条目模板.md           # 单条 Bug 的标准记录模板
```

## 分类规则（一个 Bug 归哪类）

| 分类 | 判定标准 | 典型场景 | 示例 |
|---|---|---|---|
| **独立需求 Bug** | 问题**只影响某一个需求/功能模块**，其他功能不受牵连 | 「JD 匹配分析」的某个按钮失灵；「投递追踪」的日期格式错误；「导出 Word」的样式缺失 | BUG-01 添加联系方式失效（编辑器基本信息模块） |
| **全盘 Bug** | 问题**跨功能/全局生效**：影响布局、路由、数据层、面板交互、性能或兼容性，多个功能共同受影响 | 平板布局溢出（所有配置面板不可达）；面板互斥折叠；导出后菜单收起；控制台报错；数据丢失风险 | BUG-02 ~ BUG-06 |
| **每日巡检 Bug** | 通过**日常巡检/定期回归**发现的问题（往往较隐蔽、偶发、或在新环境/新数据下暴露） | 每次发版后的例行回归；随机数据压测；不同浏览器/分辨率抽查 | 待积累 |

> 判定口诀：**影响面** —— 只打一个模块 → 独立需求 Bug；打到布局/路由/数据/交互底座 → 全盘 Bug；巡检/回归中发现（无论影响面）→ 优先记入每日巡检 Bug。

## 命名规范

- 每份清单 / 每条 Bug 独立成文件，命名：`YYYY-MM-DD-主题.md`
  - 示例：`2026-09-21-功能测试-Bug清单.md`、`2026-09-22-巡检-JD匹配按钮失灵.md`
- 一份**测试轮次清单**（如本次全功能测试）整体归档时，一个文件可包含多条 Bug（见 `分类-全盘Bug/功能测试-Bug清单.md`）；
- **单条 Bug** 单独记录时，使用 `模板/Bug条目模板.md` 的字段。

## Bug 生命周期（建议）

```
发现 → 按分类归档（含现象 + 复现步骤 + 根因） → 指派修复 → 按「回归验证建议」验证 → 关闭（更新状态字段）
```

- 每条 Bug 记录中保留 `状态` 字段：`待修复` / `修复中` / `已修复待验证` / `已关闭` / `待复现`。
- 修复后**不要删除原记录**，改状态即可，保留历史可追溯。
