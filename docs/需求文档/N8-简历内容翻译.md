# N8 简历内容翻译

> 编号：N8　优先级：P2　借鉴来源：Magic Resume（one-click translation，格式保留）　状态：待评审

---

## 一、背景与竞品参照

**Magic Resume** 的「一键翻译」：把简历翻译成任意语言，**格式保留**。这是中文求职者的强需求——投外企/海外面试需要英文简历，而逐条重写既慢又易漏。

**本项目现状**：N4 只覆盖「界面 i18n（按钮/菜单中英切换）」，**未覆盖「简历内容翻译」**。这是评审发现的缺口：界面多语言和简历内容翻译是两个不同需求，被 N4 的标题「多语言」含糊地带过了。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 投外企需要英文简历，逐条重写慢 | 一键翻译，格式/排版保留 |
| 中英简历要人工同步维护 | 翻译成独立派生版，互不覆盖 |

---

## 三、需求描述

### 3.1 功能点

**F1 一键翻译**：整份简历或选中板块，翻译为目标语言（中→英、英→中优先），**格式/排版/主题保留**。

**F2 翻译成派生版**：翻译结果生成**派生版**（复用 D3 `derive` + `kind`，`kind` 增加 `translated` 或复用 `derived` + 语言标记），不覆盖原简历。

**F3 逐段审阅**：翻译结果遵守 AI 五原则——Diff 审阅 + 逐条接受/拒绝，避免术语/专有名词（公司名、项目名、技术栈）被误翻。

**F4 术语保护**：可配置「不翻译词表」（公司名、人名、产品名、技术名词），翻译时原样保留。

### 3.2 交互细节

- 翻译入口：菜单「导出」组 + 简历详情区「翻译」按钮。
- 翻译中显示进度；术语命中词表原样保留，可在审阅时确认。
- 翻译结果派生版在血缘树中可见（母简历 → 英文版）。

---

## 四、数据结构

- 翻译版 = 派生版：`derive` 时 `kind` 记录语言（如 `derived:en`），`meta.lang` 标记目标语言。
- 术语词表存 localStorage 或随简历 meta（`meta.translationGlossary`）。

---

## 五、验收标准

1. 一键翻译整份简历 → 格式/排版/主题保留，只换语言。
2. 翻译结果生成派生版，不覆盖原简历。
3. 词表中的公司名/人名/技术名词被原样保留。
4. 翻译可逐段审阅、可撤销。

---

## 六、工程护栏

1. AI 五原则（Diff 审阅 / 可撤销 / guard 护栏）。
2. 术语保护是事实护栏的延伸，防止误翻硬事实。
3. LLM 走 `tools/ai-proxy.js`。
4. 遵守「四处接线」铁律 + 变异测试。

---

## 七、非目标

- **不做**在线实时翻译（不接第三方翻译 API 直连，走 AI 中转）。
- **不做**50+ 语言全量支持，先中英双向。

---

## 八、评审结论（2026-09-21）

| 评审维度 | 结论 |
|---|---|
| 护城河 | ✅ 守住（复用 D3 派生版血缘，纯增量） |
| 价值 | ✅ 中文求职者的真实痛点（投外企），与 N7 求职信多语言联动 |
| 成本 | 中（依赖 N2 AI 基建 + Key） |
| 依赖 | N2 AI 基建 + D3 血缘（均为前置） |
| **结论** | **通过，定 P2**（价值略低于 N7，因为非所有用户投外企；等 N2 基建就绪后低成本复用） |

> 与 N4 的关系：N4 是「界面语言」，N8 是「简历内容语言」，两者独立。N4 文档将同步澄清此边界。
