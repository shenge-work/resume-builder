# N9 个人求职官网导出（Portfolio Site）

> 编号：N9　优先级：P2　借鉴来源：Magic Self（PDF 简历 → 在线个人网站）+ 猫步简历（在线预览）　状态：待评审
> 设计依据：`docs/技术设计方案/个人求职官网导出-技术设计方案.md`（已完成完整设计，尚未实施）

---

## 一、背景与竞品参照

**Magic Self**（github.com/ThanosKa/magic-self，Apache 2.0）是 2026 年新晋方向：把 PDF 简历用 AI 转成**在线个人网站**，而非 PDF。其核心洞察——「在线招聘沟通里，PDF 之外再附一个个人官网链接，差异化更大」。

**本项目现状**：`docs/技术设计方案/个人求职官网导出-技术设计方案.md` 已产出完整设计（灵感来自小红书 TeleAgent 演示），ROADMAP 已登记为「未来演进」，但**需求文档缺失**，未纳入评审。本质是「同一份结构化简历数据多一种渲染格式」——在 PDF / Word / MD / JSON 之外，新增「导出为响应式单页个人官网 HTML」。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 海投 PDF 石沉大海，无差异化 | 个人官网链接让 HR 看到「深度页」 |
| 个人价值散落在简历/作品集/案例里 | 官网把它们组织成一套 |
| 简历只有一页，装不下项目详情 | 官网可展开作品集/项目卡片墙 |

---

## 三、需求描述

### 3.1 功能点

**F1 官网导出**：同一份简历数据 → 导出为响应式单页个人官网 HTML（可丢 GitHub Pages / Vercel）。

**F2 官网专属板块**：`kpi-band` 大数字带（量化成果高亮）、`project-cards` 项目卡片墙（作品集展示）两种新板块类型。

**F3 官网主题**：新粗野主义 / 杂志风等区别于简历 PDF 的官网主题。

**F4 下载 PDF 按钮**：官网页头「下载 PDF 简历」按钮（打通现有静默 PDF）。

**F5 公开前脱敏**：公开部署默认隐藏手机号/住址/身份证等敏感信息。

### 3.2 交互细节

- 导出前预览官网效果（复用 `#/portfolio/:id` 路由，多页面路由方案已预留）。
- 脱敏开关在导出时显式提示，默认开启。
- 所有数字与公司名来自已录入数据，不允许 AI 编造。

---

## 四、数据结构

- 复用结构化简历数据（`data`），新增官网专属板块类型（kpi-band / project-cards）。
- 官网主题为独立主题描述（区别于简历 PDF 主题，见 N1）。

---

## 五、验收标准

1. 同一份简历 → 导出个人官网 HTML，可在静态托管打开。
2. kpi-band / project-cards 板块正确渲染。
3. 官网页头「下载 PDF」按钮可用。
4. 默认脱敏：手机号/住址/身份证不出现。
5. 所有数字/公司名来自录入数据，无 AI 编造。

---

## 六、工程护栏

1. 官网**不替代** PDF 简历（HR 不点个人网站，定位为初筛通过后的深度页）。
2. 公开部署默认脱敏。
3. 复用现有渲染管线（`render-resume.js`），不重写引擎。
4. 遵守「四处接线」铁律 + 变异测试。

---

## 七、非目标

- **不做**绑定任何云端 Agent / 第三方托管（导出静态 HTML，用户自托管）。
- **不做**官网 CMS / 在线编辑（官网由简历数据驱动，非独立建站工具）。
- **不做**AI 自动生成官网文案（数字/公司名必须来自录入数据）。

---

## 八、评审结论（2026-09-21）

| 评审维度 | 结论 |
|---|---|
| 护城河 | ✅ 守住（复用结构化数据 + 渲染管线，纯增量导出格式；但「导出格式」已 6 种，边际收益需评估） |
| 价值 | 中（差异化投递利器，但非核心刚需；竞品 Magic Self 验证了方向） |
| 成本 | 中高（新板块类型 + 官网主题 + 脱敏，工作量不小） |
| 依赖 | N1 主题体系（官网主题可复用）；静默 PDF（F4 下载按钮） |
| **结论** | **通过，定 P2**；建议**先做 P1 子集**（主题 + 板块 + 导出 + 脱敏，不依赖 AI），AI 梳理链路留 P2 与 AI 基建衔接 |
