# N5 简历缩略图仪表盘

> 编号：N5　优先级：P3（评审下调）　借鉴来源：Reactive Resume（dashboard 简历缩略图预览）　状态：待开发
> 评审结论：✅ 通过，降为 P3（2026-09-21）

---

## 一、背景与竞品参照

**Reactive Resume** 的仪表盘（dashboard）中，每份简历以**缩略图卡片**呈现，一眼识别哪份是哪份，而非只靠标题文字。

**本项目现状**：简历库左抽屉用「标题 + 徽标（定制版）」文字列表呈现（`renderResumeDrawer`），多份简历时辨识度低——尤其「母简历 vs 多个派生版」血缘关系不直观。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 简历多了靠标题猜内容 | 缩略图一眼识别版式与内容 |
| 派生版血缘靠文字徽标，不直观 | 缩略图 + 血缘层级可视化 |

---

## 三、需求描述

### 3.1 功能点

**F1 简历缩略图**：简历库卡片生成简历首页的缩略图（基于当前 payload 渲染迷你预览），随内容更新而刷新。

**F2 血缘层级可视化（可选增强）**：母简历卡片下缩进显示其派生版（利用已落地的 `parentId`/`children`），形成「母 → 派生」树形，比平铺列表更直观。

**F3 卡片信息增强**：卡片显示标题、更新时间、定制版徽标、缩略图、标签（tags）。

### 3.2 交互细节

- 缩略图懒加载/缓存，避免多份简历时卡顿（`renderResumeDrawer` 每次全量刷新，需注意性能）。
- 缩略图是**预览用**，不可点击编辑，点击整卡进入该简历。
- 血缘树可折叠/展开。

### 3.3 边界与异常

- 简历为空/新建时显示占位缩略图（空纸张轮廓）。
- 生成缩略图用轻量方式（复用渲染逻辑输出到小尺寸容器，不额外截图依赖）。

---

## 四、数据结构

- 复用现有 `parentId`/`children`，无需新增存储字段。
- 缩略图缓存可用内存态（不落盘），内容变化时失效重建。

---

## 五、验收标准

1. 简历库每份简历显示缩略图，且随内容更新刷新。
2. 派生版在母简历下缩进显示，血缘关系清晰。
3. 空简历显示占位缩略图，不报错。
4. 多份简历时抽屉渲染不卡顿（性能可接受）。

---

## 六、工程护栏

1. `renderResumeDrawer` 全量刷新是既有性能点，缩略图须懒加载/缓存，勿加重每键重渲染。
2. 遵守「四处接线」铁律 + 变异测试。
3. PII 隔离（缩略图即简历内容，测试用虚构数据）。

---

## 七、非目标

- **不做**服务端图片托管/缩略图上传。
- **不做**拖拽调整简历排序（卡片排序可后续与主题板块排序统一，另行立项）。

---

## 八、评审结论（2026-09-21）

| 评审维度 | 结论 |
|---|---|
| 护城河 | ✅ 守住（纯 UI 增强） |
| 价值 | 低（辨识度优化，非主线；且 #/library 卡片网格已存在，缩略图是锦上添花） |
| 成本 | 中（缩略图懒加载/缓存需防性能回退） |
| 依赖 | 无 |
| **结论** | **通过，降为 P3**——价值偏低，且「血缘层级可视化」部分可并入 D3 血缘的 UI 优化，避免单独立项 |
