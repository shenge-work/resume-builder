# N10 多云存储后端适配（本地磁盘 + 多网盘/云文档）

> 编号：N10　优先级：P1　借鉴来源：alist（30+ 网盘聚合）/ fundrive（统一 BaseDrive 抽象）/ pan-sdk（Go 网盘驱动库）　状态：待评审

> 调研与可行性验证：✅ 已完成（2026-09-21），结论见 §八

## 一、背景与需求本质

本产品**不接入数据库、不建后端**，最终交付物是**移动端（Android）+ PC（Windows/macOS/Linux）可安装的软件包**。数据存储只有两种：

1. **本地**：用户设备的本地磁盘（已实现：桌面端系统用户数据目录，浏览器端 `data/resumes/`）；
2. **云端**：借「大众用户免费用得起的网盘 / 云文档平台」做存储后端——百度网盘、阿里云盘、夸克网盘、123 云盘、有道云笔记、腾讯微云、飞书、钉钉、ima 等。

**本质**：把「简历 = 一个文件」的同步/备份能力，**嫁接到用户已经拥有的网盘上**，而不是自建云服务。用户不用注册新账号，数据仍归用户自己掌控（延续「数据自持」护城河）。

## 二、竞品与开源最佳实践（调研结论）

### 2.1 已有成熟开源实现（证明「多网盘抽象」是已被验证的通用模式）

| 项目 | 语言 | 亮点 | 对本需求的借鉴 |
|---|---|---|---|
| **alist**（AlistGo/alist，★50k+，AGPL） | Go | **30+ 网盘聚合**（阿里/百度/夸克/123/115/天翼/Google Drive/OneDrive…）+ 统一 WebDAV 出口 | **多网盘驱动层的最佳参照**；AGPL 传染性需注意（不能直接抄代码） |
| **fundrive**（elitever/fundrive，Python） | Python | **统一 `BaseDrive` 抽象**：`upload_file/download_file/mkdir/get_file_list/rename/move/delete`，支持 OSS/阿里云盘/百度云盘/蓝奏/github/gitee | **「同一套接口读各种网盘」思想，与本项目 `ResumeDataSourceRegistry` 完全同构** |
| **pan-sdk**（gitee，Go） | Go | `driver.Driver` 统一接口 + 阿里/百度/夸克/迅雷/蓝奏 | 同上，驱动即插即用 |
| jakeslee/aliyundrive、go-aliyundrive | Go | 阿里云盘单家 SDK（秒传/分片/断点） | 单家适配时参考 |

**关键结论**：**「多网盘抽象层」是成熟且被广泛验证的模式**，本项目的 `ResumeDataSourceRegistry`（`js/store/datasource.js`）已经是这个模式的最佳实践雏形——飞书就是一个 `DataSourceAdapter`。新网盘只需实现同一接口注册进来，**架构上零障碍**。

### 2.2 各平台开放情况（逐平台调研，决定优先级）

| 平台 | 开放 API | OAuth 授权 | 关键限制 | 可行性 |
|---|---|---|---|---|
| **飞书** | ✅ 云文档/云盘 API 完整 | ✅ 用户身份（user_access_token，本项目已实现扫码） | 无 | ✅ **已落地** |
| **阿里云盘** | ✅ 网盘与相册服务 PDS + Open API | ✅ OAuth2.0 用户身份 | 需注册应用（appid/secret） | ✅ **高可行** |
| **百度网盘** | ✅ Open API（REST，分片/断点续传） | ✅ OAuth2.0（scope=basic,netdisk） | ⚠️ **个人开发者网盘 API 需企业资质认证**（最大障碍）；token 30 天 + refresh 长效 | ⚠️ **中可行（认证门槛）** |
| **夸克网盘** | ✅（alist/pan-sdk 均已支持） | ✅ Cookie/扫码 | 接口非官方公开，靠逆向，稳定性风险 | ⚠️ 中（非官方） |
| **钉钉** | ✅ 存储 API（storage/spaces） | ✅ access_token | ⚠️ **主要面向企业内部应用**，个人用户场景受限 | ⚠️ 中（企业向） |
| **有道云笔记** | ✅ 群组文件 OpenAPI（上传/下载笔记） | ✅ | ⚠️ 偏「群组/协作」场景，个人笔记 API 开放度低 | ⚠️ 低-中 |
| **腾讯微云** | ⚠️ 开放度低（无公开个人 API，alist 支持但靠非官方接口） | ⚠️ | 非官方接口 | ⚠️ 低 |
| **ima（腾讯）** | ❌ 未开放个人 API（ima 是知识库产品） | ❌ | 无 | ❌ **不可行** |

**优先级结论**：**阿里云盘 > 百度网盘 > 夸克 > 钉钉**。ima、腾讯微云、有道云笔记因开放度低或不可行，**暂不接入**（保留适配器扩展位）。

## 三、需求描述

### 3.1 总体设计（架构零障碍）

本项目已有多数据源架构，本需求是**在此之上扩展适配器**，不推翻现有架构：

```
                    ResumeDataSourceRegistry（已存在）
                    ├── adapter-local.js       （本地磁盘，已落地）
                    ├── adapter-feishu.js      （飞书，已落地）
                    ├── adapter-aliyundrive.js （阿里云盘，新增）
                    ├── adapter-baidupan.js    （百度网盘，新增）
                    └── adapter-quark.js       （夸克网盘，新增，可选）
```

每个适配器实现 `datasource.js` 定义的标准契约（`listDocuments/readDocument/writeDocument/listVersions/restoreVersion/loadConfig/saveConfig` + `capabilities` 声明）。

### 3.2 功能点

**F1 多云适配器框架**：把「本地 / 飞书 / 网盘」统一到一个数据源选择器里，用户可设置默认云存储（当前仅飞书，扩展为多选）。

**F2 阿里云盘适配器**（P1 首选）：OAuth2.0 扫码授权 → 读写 `resumes/` 目录下的简历 JSON 文件；秒传 + 断点续传。

**F3 百度网盘适配器**（P1，需认证）：OAuth2.0 授权（`scope=basic,netdisk`）→ 读写指定目录；分片上传 + 断点续传。

**F4 夸克网盘适配器**（P2，可选）：Cookie/扫码授权，接口非官方，标注「实验性」。

**F5 版本历史兜底**：网盘平台有版本历史则用（如飞书），无版本历史的平台用「文件名带时间戳」或「本地快照」兜底（延续「不丢数据」铁律）。

**F6 数据可移植**：任何云存储都能导出/导入 JSON，随时换平台不锁死。

### 3.3 交互细节

- 设置页「数据」分组显示所有数据源，标注「已配置 / 未配置 / 不可用」。
- 授权方式：扫码（OAuth）优先，贴合「大众用户免费用」的定位。
- 能力降级：`capabilities` 声明驱动 UI——无 `versions` 的平台不显示「版本历史」入口；`oauth: 'none'` 的平台显示「需手动配置」。
- 降级告警：云写入失败时，走 `httpBackendWithFallback` 静默降级 + `onDegrade` 通知（延续现有保存状态条逻辑）。

## 四、数据结构

- 新增适配器文件：`js/store/adapter-aliyundrive.js`、`adapter-baidupan.js` 等，实现 `datasource.js` 契约。
- 凭证存储：延续「凭证只存本机、绝不进浏览器」铁律——桌面端存系统钥匙串/应用数据目录（`sync.config.json` 扩展为多平台凭证），浏览器端由 `tools/serve.js` 中转（token 存 gitignored 配置文件，浏览器只拿中转结果）。
- 云端文件模型：**每份简历 = 一个 JSON 文件**，放在网盘的一个固定目录（如 `resume-builder/`），与本地分文件模型同构。

---

## 五、验收标准

1. 阿里云盘：扫码授权 → 写入一份简历 JSON → 换设备读回 → 内容一致。
2. 百度网盘：OAuth 授权 → 上传/下载/断点续传正常（大文件分片）。
3. 数据源选择器：可切换默认云存储，未配置的平台正确降级（不报错、不假装成功）。
4. 版本历史：有版本历史的平台可列版本 + 恢复；无版本历史平台用快照兜底。
5. 凭证安全：任何云平台的 token/secret 不出现在浏览器/前端代码里。
6. 数据可移植：任意平台可导出 JSON，导入到另一平台/本地。

---

## 六、工程护栏

1. **凭证安全（最高优先级）**：延续「凭证只存本机、绝不进浏览器」铁律；新增网盘的 app_id/secret/token 一律走 `tools/serve.js` 中转 + gitignored 配置文件，前端拿不到裸凭证。
2. **alist 是 AGPL**：**只借鉴其「驱动层架构思想」，不抄代码**（AGPL 传染性会污染本项目 MIT 协议）。
3. **非官方接口（夸克）标注实验性**：逆向接口随时可能失效，不得作为默认推荐，出问题不承诺修复。
4. 新增适配器遵守「四处接线」铁律（index.html / build-single.js / run.js / 重建 dist）+ 变异测试。
5. 写盘走 `currentPayload()` + savedAt，禁止自拼对象。
6. PII 隔离：测试用虚构数据，云凭证不进 git。

---

## 七、非目标

- **不做**自建云服务 / 后端 / 数据库（守住「零后端」）。
- **不做** ima、腾讯微云、有道云笔记接入（开放度低/不可行，保留扩展位）。
- **不抄** alist 代码（AGPL 传染）。
- **不做**多端实时协作（那是编辑器级冲突合并，见 ROADMAP，另立项）。
- **不做**网盘内文件的全量同步引擎（只同步简历 JSON，不做通用文件同步器）。

## 八、调研结论与可行性验证

### 8.1 可行性结论

| 问题 | 结论 |
|---|---|
| 各平台是否支持第三方读写 | ✅ 阿里云盘/百度网盘/飞书/钉钉支持 OAuth + 文件 API；夸克靠非官方接口；ima/腾讯微云/有道不可行或开放度低 |
| 是否有成熟开源实现 | ✅ **alist（30+ 网盘）、fundrive（统一 BaseDrive）、pan-sdk（Go 驱动库）** 均验证了「多网盘抽象层」模式成熟 |
| 本项目能否落地 | ✅ **架构零障碍**——`ResumeDataSourceRegistry` 已是同构的最佳实践，飞书适配器即模板 |
| 最大风险 | ⚠️ ① 百度网盘个人开发者需企业认证；② 夸克等非官方接口稳定性；③ alist 是 AGPL 不能抄 |

### 8.2 落地方案（分阶段）

| 阶段 | 内容 | 预估成本 |
|---|---|---|
| 阶段 1 | 多云适配器框架收口 + 阿里云盘适配器（官方 API 最稳，P1） | 3–5 天 |
| 阶段 2 | 百度网盘适配器（需先解决企业认证，或提供「用户自建应用填 app_id」兜底） | 3–5 天 |
| 阶段 3 | 夸克网盘（实验性，可选） | 2–3 天 |

### 8.3 评审结论

| 评审维度 | 结论 |
|---|---|
| 护城河 | ✅ **强化「数据自持」护城河**——把「数据自己掌控」从「本地 + 飞书」扩展到「任意网盘」，进一步摆脱对单一平台的依赖 |
| 价值 | 高（大众用户本来就有网盘，无需注册新账号；是「跨端同步」的普适解） |
| 成本 | 中高（每平台一个适配器，但框架已就绪，单个适配器成本可控） |
| 依赖 | 复用 `datasource.js` 契约 + `tools/serve.js` 中转；无阻塞依赖 |
| **结论** | **通过，定 P1**；但**分期交付**——先做框架收口 + 阿里云盘（官方稳定），百度网盘视认证门槛再定，夸克列实验性 |
