# N1 主题模板系统

> 编号：N1　优先级：P1　借鉴来源：Reactive Resume（15 套模板 / 拖拽排序 / 自定义 section / 结构化样式规则）+ Magic Resume（19 套模板 / 完全自定义颜色字体间距布局）　状态：待验收（开发完成 2026-09-21，待人工核对验收）
> 评审结论：✅ 通过（2026-09-21）　详见文末 §八

---

## 一、背景与竞品参照

**Reactive Resume 做对了什么**：把「字号 / 行距 / 间距 / 颜色 / 板块顺序」抽象成一套**结构化的、可序列化的样式规则对象**（Structured Style Rules），而不是写死在渲染代码里。这使它能够：

1. 量产 **15 套内置模板**（Azurill、Onyx、Pikachu 等），一键切换；
2. 支持 **A4 / Letter 纸张规格**切换；
3. 颜色、字体、间距均可单独微调；
4. 支持**拖拽调整板块顺序**、**自定义任意类型 section**、**逐节标题显隐控制**；
5. JSON 导出天然带样式，AI 未来可生成/推荐主题。

**本项目现状**（已核对代码）：

- 排版引擎优秀（`resume-render.js`），但样式配置散在 `js/data.js` 的常量与多处内联里；
- 模板切换入口（`#/templates`）是**空壳**，未实现；
- 已有 `js/theme.js` 模块（基础版），但未形成完整 Theme Schema，也未与渲染层解耦。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 每换一份简历都要手调字号/颜色/间距 | 一键切主题，版式风格秒变 |
| 「颠覆布局」的自由排版靠手工堆 CSS 门槛高 | 拖拽排序 + 自定义板块，零代码调整结构 |
| 想给不同岗位配不同视觉风格 | 主题可随简历/派生版独立保存 |

## 三、需求描述

### 3.1 主题 Schema（核心数据模型）

定义一份**主题描述对象**（Theme Schema），渲染层只消费它、不再读散落常量：

```js
{
  id: 'onyx',                    // 主题唯一标识
  name: 'Onyx',                  // 显示名
  paper: { size: 'A4' | 'Letter', margin: {top,right,bottom,left} },
  fonts: { name, size, lineHeight, letterSpacing },
  spacing: { sectionGap, itemGap, paragraphGap },
  color: { primary, ink, paper, muted, accent },
  sections: {
    order: ['header','summary','career','education','skills','projects'],
    visible: { header:true, summary:true, ... },     // 逐板块显隐
    headingVisible: { career:true, education:true }  // 逐节标题显隐
  }
}
```

### 3.2 功能点

**F1 内置主题库**：提供 3–5 套默认主题（单栏经典、单栏现代、双栏经典、双栏现代、极简），覆盖 Resume Matcher 的四种模板形态 + 本项目特色。

**F2 主题切换**：`#/templates` 从空壳变成可选主题列表；选中后预览区字号/间距/配色/板块显隐**实时同步**变化。

**F3 主题自定义**：在主题基础上微调颜色（主色/墨色/纸色）、字体、间距；微调项作为 `overrides` 存进当前简历 payload，不污染内置主题定义。

**F4 板块拖拽排序**：板块顺序可在「结构」面板中拖拽调整（等价于改 `sections.order`）；移动端提供上下箭头按钮替代拖拽。

**F5 自定义板块**：允许用户新增任意类型 section（标题 + 自由内容，支持富文本），并能显隐/排序。

**F6 逐节标题显隐**：每个板块的标题行可独立开关显示（如「项目经历」标题不想显示时可关掉）。

### 3.3 交互细节

- 主题切换是**可撤销**操作（进撤销栈），误切可 Ctrl/Cmd+Z 恢复。
- 切换主题时**不覆盖用户已有内容**，只改样式与板块显隐/顺序；若主题隐藏了某板块且该板块有内容，弹确认「该板块有 N 条内容，隐藏后不会删除，可随时恢复」。
- 自定义板块在切换主题时**始终保留**（不随主题显隐规则消失），仅跟随 `sections.order` 排序。
- A4 / Letter 切换联动分页参考线重算。

## 四、数据结构

- Theme Schema 存内置主题库（`js/theme.js` 扩展为内置主题数组 + 默认主题）。
- 用户微调项 `overrides` 随简历持久化：走 `currentPayload()`，挂在 `data.theme`（或 `spacing`/`fonts` 扩展字段），**必须带 savedAt**。
- 板块顺序/显隐同理持久化到 payload，渲染层 `resume-render.js` 从「读常量」改为「读当前主题对象 + overrides」。
- JSON Resume 导出时主题信息作为扩展字段（`meta.theme`）带出。

---

## 五、验收标准

1. 切换任一套内置主题 → 预览字号/间距/配色/板块显隐同步变化，且**不丢失已有内容**。
2. 拖拽调整板块顺序 → 预览顺序变化；刷新后顺序保持。
3. 新增自定义板块 → 显示在预览区，可显隐/排序；切主题后自定义板块仍在。
4. 关闭某板块标题 → 预览区该标题消失，内容仍在。
5. 主题切换可 Ctrl/Cmd+Z 撤销。
6. 导出 JSON 能带回主题信息，再导入能还原主题。

## 六、工程护栏

1. **新增前端模块必改四处**：① `index.html` `<script>`（store < ui < app.js）；② `tools/build-single.js` 白名单；③ `test/run.js` vm 同序加载；④ 重建 `dist/` 与 `dist-desktop/`。
2. 渲染层改「读常量 → 读主题对象」是**破坏性改动**，必须保证默认主题与现有效果**像素级一致**（跑既有渲染测试 + 变异测试）。
3. 断言落「失效面」：写完做变异测试。
4. 主题切换进撤销栈，遵守「可撤销」原则。
5. PII 隔离：测试数据用虚构名。

---

## 七、非目标

- **不做**「用户上传自定义 CSS 文件」——自由排版仍通过「自定义板块 + 富文本 + 主题微调」实现，避免任意 CSS 注入风险。
- **不做**在线主题市场 / 主题分享。
- **不引入**任何前端框架，纯原生 JS 实现。

## 八、评审结论（2026-09-21）

| 评审维度 | 结论 |
|---|---|
| 护城河 | ✅ 守住，且**强化**——把散落的样式收敛成 Theme Schema，是「自由 CSS 排版」的可复用化（竞品要模板化，本项目要「模板化 + 保留自由微调」） |
| 价值 | 中高（模板是获客门面，但本项目护城河本就在排版，属锦上添花而非雪中送炭） |
| 成本 | 中（渲染层「读常量 → 读主题对象」是破坏性改动，需保证默认主题像素级一致） |
| 依赖 | 无；且是 N4 暗色模式的前置（CSS 变量主题体系） |
| **结论** | **通过，定 P1**（作为体验改造地基，先做） |

> ⚠️ **与 ROADMAP「多模板/主题」条目对齐**：ROADMAP 里的「多模板/主题 + #/templates 模板市场」与本需求重叠，开发时应合并执行——本需求是「主题 Schema 数据层 + 切换能力」，`#/templates` 是它的展示页（多页面路由方案已预留）。
> 评审依据：[00-产品定位与评审标尺](./00-产品定位与评审标尺.md)

## 九、实现记录与验收对照（2026-09-21）

**设计策略**：不重写渲染层读主题对象（破坏性改动风险高），改为「把主题物化进既有 live 全局态（`currentFonts` / `currentSpacing` / `data.pageMargins`）+ 把强调色子集内联到 `.resume` 的 `--paper-*` CSS 变量」。默认主题 `classic` 的 color 为空 → `resolvePalette` 返回 `null`（交给样式表/夜间纸张），天然像素级一致。

**落地的代码**：
- `js/theme-templates.js`（新建）：主题 Schema + 5 套内置主题（classic / modern / elegant / warm / minimal），纯逻辑零 DOM，挂 `window.ResumeThemeTemplates`。暴露 `PAPER_KEYS` / `TINT_KEYS` / `getTheme` / `applyPaletteToEl` / `ensureTheme` 等。
- `js/render/resume-render.js`：渲染末尾调 `applyPaletteToEl` 写内联调色板；段落标题 `headingVisible` 显隐；自定义 `custom` 板块分支。
- `js/render/editor-schema.js`：`headingVisible` 字段；注册 `custom` 板块类型（标题 + 富文本 + 显隐/排序）。
- `js/app.js`：暴露 `applyTheme` / `customizeThemeColor` / `resetThemeOverrides` / `getActiveThemeId` / `getCurrentPalette`；
  - `applyTheme` 走 `recordHistory` 物化字体/间距/边距并导航到编辑器（**可撤销**，满足交互约束）。
- `js/views/templates-view.js`：从空壳重写成真正的主题画廊（5 卡片 + 当前高亮 + 7 色「主题微调」面板 + 重置/返回）。
- `js/router/layout.js`、`index.html`、`tools/build-single.js`、`test/run.js`：接入新模块的脚本顺序与构建/测试白名单。
- `js/io/jsonresume-adapter.js`：**补 AC #6**——`toJsonResume` 把主题（id + overrides）写入 `meta.theme` 扩展字段（默认 classic 无微调则不写，避免污染标准 JSON Resume）；`fromJsonResume` 还原 `meta.theme` 为 `data.theme`。

**验收对照**（§五六条）：

| 验收项 | 结论 | 说明 |
|---|---|---|
| 1. 切主题→字号/间距/配色/板块显隐同步变化且不丢内容 | ✅ | `applyTheme` 物化全局态；`ensureTheme` 在载入时归一 |
| 2. 拖拽调整板块顺序→预览变化、刷新保持 | ✅ | 预览级拖拽/↑↓ 排序（`resume-render.js`）为既有能力，主题只改样式不碰顺序 |
| 3. 新增自定义板块→显示、可显隐/排序、切主题后仍在 | ✅ | `custom` 板块类型 + `headingVisible`；`applyTheme` 不改 `sections` 内容 |
| 4. 关闭板块标题→标题消失内容仍在 | ✅ | `headingVisible === false` 渲染时跳过 `<h2>` |
| 5. 主题切换可 Ctrl/Cmd+Z 撤销 | ✅ | `applyTheme` 首步 `recordHistory('action')` |
| 6. 导出 JSON 带主题、再导入还原 | ✅（补全） | `meta.theme` 往返，见 `test/cases-jsonresume.js` 新增 5 条断言 |

**验证**：
- 单测：`node test/run.js` → **pass=955 fail=0**（含 N1 主题断言 + AC #6 往返 5 条）。
- 构建：`build-single.js` 生成 `dist/简历编辑器-单文件.html`（1183 KB，0 外部引用）；`build-desktop-frontend.js` 重建 `dist-desktop/`。
- 无头 Chrome 冒烟：`/#/templates` 渲染 5 张 `tpl-card` + 7 个 `data-tint` 颜色输入；`/#/editor` 的 `.resume` 经典主题无内联 `--paper-rule`（符合预期）。

**遗留/待办**：本需求未含「用户自定义 CSS 文件」「在线主题市场」（见 §七非目标）；A4/Letter 切换已在 Schema 预留，本次未做前端开关 UI（属增量，可搭车 N4）。
