# N7 求职信与面试准备

> 编号：N7　优先级：P1（等 Key，与 N2 同期）　借鉴来源：Resume Matcher（Cover Letter + Interview Prep）+ Reactive Resume（求职信共享库）+ Magic Resume（interview 模式）　状态：待评审

---

## 一、背景与竞品参照

**Resume Matcher** 的核心闭环不是「润色」，而是「**一份母简历 → JD 定制版 → 求职信 → 面试准备 → PDF**」的完整投递 prep。它明确提供：

1. **Cover Letter Generator**：基于 JD + 简历生成定制求职信；
2. **Interview Preparation**：基于已保存的定制版简历，生成结构化、简历锚定的面试准备（可手动触发，或设置里开启自动生成）。

**Reactive Resume** 有**求职信共享库**（cover letters 复用简历样式）。**Magic Resume** 有独立的 `interview` 模式。

**本项目现状**：N2 只覆盖「润色」，把「求职信/面试准备」列为「另行立项」却未立项——这是评审发现的**最大缺口**，因为竞品证明「求职信 + 面试准备」才是用户「投一个岗」的完整闭环，也是付费意愿最强的一环。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 投递要简历 + 求职信，求职信要重写 | JD 一键生成定制求职信 |
| 面试前不知准备什么 | 基于自己简历 + JD 生成结构化面试准备 |
| 求职信散落难复用 | 求职信随简历/JD 关联保存 |

---

## 三、需求描述

### 3.1 功能点

**F1 求职信生成**：输入 JD（复用 D3 已持久化的 JD）+ 母/定制版简历 → AI 生成定制求职信（格式可套用简历主题）。

**F2 求职信库**：求职信随简历/JD 关联保存（复用 `parentId`/`jobId` 血缘），可复用、可复用简历样式。

**F3 面试准备生成**：基于定制版简历 + JD，生成结构化面试准备（常见问题 + 结合自己经历的回答要点 + 项目深挖点）。

**F4 多语言求职信**：支持生成中/英求职信（衔接 N8 翻译能力）。

### 3.2 交互细节

- 求职信/面试准备同样遵守「Diff 审阅 + 人工审批 + 可撤销」的 AI 五原则（与 N2 同源交互）。
- 面试准备在投递追踪（D6）的「一面/二面」状态处提供快捷入口。
- 求职信存为简历的附属实体（不是独立简历），在简历详情/血缘树中可见。

---

## 四、数据结构

- 求职信复用 `meta` 血缘字段（`parentId`/`jobId`），或新增 `meta.coverLetter` 子对象。
- 面试准备可存 `meta.interviewPrep` 或按需即时生成不落盘（建议即时生成 + 可选保存）。
- AI 请求走 `tools/ai-proxy.js`，Key 存 gitignored `ai.config.json`。

---

## 五、验收标准

1. 粘贴 JD（或选已存 JD）→ 生成定制求职信，套用简历主题。
2. 求职信随简历/JD 关联保存，可复用。
3. 生成结构化面试准备，内容锚定自己的简历经历（非泛泛而谈）。
4. 求职信/面试准备遵守 Diff 审阅 + 可撤销。
5. 中/英求职信可切换。

---

## 六、工程护栏

1. AI 五原则（Diff 审阅 / 范围显式 / 可撤销 / guard 护栏 / 可脱敏）同样适用于求职信与面试准备。
2. 事实护栏拦截编造的公司名/数字/经历。
3. LLM 禁浏览器直连，走 `tools/ai-proxy.js`。
4. 遵守「四处接线」铁律 + 变异测试。
5. Key/PII 不进入 git。

---

## 七、非目标

- **不做**面试模拟对话（语音/视频 mock interview）——本期只做「结构化准备文本」，实时 mock 是更重的产品，另行评估。
- **不做**求职信自动投递/发送（对接邮箱/招聘平台）。
- **不做**职业规划/行业赛道推荐（那是更泛的生涯服务）。
