# N6 导出引导与格式提示

> 编号：N6　优先级：P3　借鉴来源：竞品导出对比引申（纯 UX，非抄代码）　状态：待验收（F1/F2/F3 已落地）
> 评审结论：✅ 通过，定 P3（2026-09-21）

---

## 一、背景与竞品参照

**本项目导出分三类**（已核对代码）：

| 方式 | 特点 |
|---|---|
| 静默 PDF（Chrome headless） | 文字可选中、矢量，但依赖本地 Chrome + `npm start`，无 Chrome 报 501 |
| 图片版 PDF / 长图 | 版式 100% 一致，但文字不可选、体积大 |
| 单文件 HTML | 文字可选中，但不是 PDF |

竞品（Reactive Resume / OpenResume）用纯客户端 react-pdf 解决了「文字可选中 + 不依赖服务端」，但代价是**放弃自由 CSS**——与本项目护城河冲突，故不抄引擎，只学**「让用户知道该选哪个」的引导**。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 导出时不知道该选哪种格式 | 明确提示各格式的适用场景与差异 |
| 静默 PDF 无 Chrome 时报 501 看不懂 | 报错给出可行动的替代路径 |
| 图片版 PDF 文字不可选被 ATS 刷掉 | 引导「文字可选中请用打印」 |

---

## 三、需求描述

### 3.1 功能点

**F1 导出格式对比提示**：导出弹窗中对每种格式附一句话说明其特点（文字是否可选中 / 是否依赖 Chrome / 体积大小 / 适用场景）。

**F2 图片版 PDF 旁引导**：在「图片版 PDF」选项旁提示「如需文字可选中，请用单文件 HTML → 浏览器打印另存 PDF」。

**F3 静默 PDF 失败的可行动提示**：当 `/api/pdf` 返回 501（无 Chrome）时，不是干巴巴报错，而是给出「请先 `npm start` 或改用图片版/单文件 HTML」的明确引导。

### 3.2 交互细节

- 引导文案轻量，不打断主流程（tooltip / 次要说明文字）。
- 错误提示带可点击的替代方案入口（直接跳到另一导出方式）。

---

## 四、数据结构

- 无存储/schema 变更，纯 UI 文案与错误处理。

---

## 五、验收标准

1. 导出弹窗每种格式有清晰的一句话说明。
2. 图片版 PDF 旁有「文字可选中」替代引导。
3. `/api/pdf` 501 时提示可行动，而非裸错误码。
4. 不影响既有导出功能。

---

## 六、工程护栏

1. 只改 UI 文案与错误分支，不重构导出引擎。
2. 错误提示文案统一走 `notifier`/提示组件，不硬编码散落。
3. 遵守变异测试（错误分支的提示需可测）。

---

## 七、非目标

- **不引入** react-pdf / 客户端 PDF 引擎（与自由 CSS 护城河冲突）。
- **不改**现有三种导出的底层实现。

## 九、实现记录与验收对照（2026-09-21）

**实现要点**
- **F1/F2（格式对比提示）**：`js/ui/menu-actions.js` 的「导出」组每个入口新增一行 `desc`（文字是否可选中 / 是否依赖 Chrome / 体积 / 适用场景），`itemHtml` 渲染为 `.menu-desc` 子节点（桌面/手机两端均输出）；图片版 PDF 的 `desc` 明确标注「文字不可选中」，单文件 HTML 的 `desc` 给出「打印另存 PDF」的可选中路径。
- **F3（静默 PDF 失败的可行动提示）**：`js/export-extra.js` 的 `exportPdfSilent` 此前只报「静默导出失败」；现在 `errorFromResponse` 把 HTTP 状态码 / `NO_BROWSER` 业务码带上，501 时给出明确引导（需 `npm start` / 改用单文件 HTML 或图片版），并直接打开打印对话框作为备选。决策逻辑抽到纯函数 `pdfSilentFailureMessage`（可变异测试）。

**验收对照**
| 验收标准 | 结果 |
|---|---|
| 1. 导出弹窗每种格式有清晰的一句话说明 | ✅ 每个导出入口附 `desc` |
| 2. 图片版 PDF 旁有「文字可选中」替代引导 | ✅ 图片版 desc 标注不可选中 + 单文件 HTML desc 给打印路径 |
| 3. `/api/pdf` 501 时提示可行动，而非裸错误码 | ✅ `pdfSilentFailureMessage(501)` 明确引导 + 自动打开打印 |
| 4. 不影响既有导出功能 | ✅ 仅加文案与错误分支，导出引擎零改动 |

**测试**：`test/cases-menu.js` 加 3 条（导出项均带 desc / 图片版·单文件 HTML 引导 / 两端渲染 `.menu-desc`）；`test/cases-export.js` 加 2 条（`pdfSilentFailureMessage` 501 vs 非 501 互斥，含变异保护）；`node test/run.js` 全绿（1001/0）。

> 按「六、工程护栏」未重构导出引擎；501 提示文案统一经 `notify` 走自动保存提示位，未硬编码散落。
