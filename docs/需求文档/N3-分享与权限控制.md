# N3 分享与权限控制

> 编号：N3　优先级：P2　借鉴来源：Reactive Resume（isPublic / isLocked / 唯一链接分享 / 完整数据导出 / 一键删除）+ Magic Resume（Viewer / Commenter / Editor 三级分享权限）　状态：待验收（开发完成 2026-09-21）
> 评审结论：✅ 通过（2026-09-21）　详见文末 §八　实现记录与验收对照见 §九

---

## 一、背景与竞品参照

**Reactive Resume 的隐私与分享模型**：

1. **`isPublic` 分享开关**——数据层标记「哪份简历允许公开分享」，而非分享时才临时决定；
2. **`isLocked` 锁定防误改**——锁定后不可编辑，防止误操作破坏已定稿简历；
3. **唯一链接分享**——生成专属链接，对方无需注册即可查看；
4. **完整数据导出**——任意时间可导出全部个人数据；
5. **一键永久删除**——彻底删除所有数据。

**Magic Resume 的分享权限分级**（更完整）：分享链接支持 **Viewer（仅查看）/ Commenter（可评论）/ Editor（可编辑）** 三级权限，而非一刀切的「公开」。

**本项目现状**：A6 已落地「导出只读分享页」（静态 HTML + 水印 + noindex），但**数据层没有 `isPublic` / `isLocked` 标记**，「哪份简历允许分享」没有显式状态；简历库也没有锁定/一键删除的粒度控制。

---

## 二、用户价值

| 痛点 | 收益 |
|---|---|
| 已定稿简历怕误改 | isLocked 锁定，编辑前需解锁 |
| 分享哪份、不分享哪份分不清 | isPublic 显式标记，一眼可见 |
| 想清空数据 / 整体备份 | 一键删除 + 完整导出 |

---

## 三、需求描述

### 3.1 功能点

**F1 简历锁定（isLocked）**：简历库中每份简历可「锁定」，锁定后编辑区只读（或编辑前弹确认解锁）；抽屉卡片显示 🔒 标识。

**F2 分享开关（isPublic）**：简历 meta 增加 `isPublic` 标记，与 A6 的「导出分享页」打通——只有 isPublic=true 的简历才允许生成分享页；未开启时分享入口置灰并提示。

**F3 唯一分享链接**：为 isPublic 简历生成唯一 token 链接（本地可生成，未来接静态托管）；链接可随时吊销（重设 token）。

**F4 完整数据导出**：一键导出全部简历（JSON 打包），含 meta（parentId/kind/jobId/tags/isPublic/isLocked）+ payload。

**F5 一键删除**：简历库支持整份删除（进回收站或二次确认），支持「全部删除」。

### 3.2 交互细节

- 锁定/解锁是轻量操作，放抽屉卡片「⋯」菜单内；锁定态下编辑区顶部显示「已锁定」提示条。
- 分享开关放「⋯」菜单或详情区；关闭分享时，已生成的旧分享页**不自动失效**（静态页已发出无法追回），但新生成被禁止——界面明确提示这一点。
- 一键删除必须**二次确认**，且支持撤销（进回收站优先，避免误删）。

---

## 四、数据结构

- `meta` 增加 `isPublic`、`isLocked` 可选字段（缺省 `false`），`create`/`save` 白名单透传（`resume-library.js` 的 `save()` 是白名单式，每个新字段显式加一行）。
- 分享 token 存 `meta.shareToken`（随机串）。
- 完整导出走 `resume-library.js` 的 list + doc 读取，打包成 JSON。

---

## 五、验收标准

1. 锁定一份简历 → 编辑区只读，解锁后恢复；抽屉显示 🔒。
2. 未开启 isPublic 的简历，分享页入口置灰；开启后可生成。
3. 生成唯一链接 → 可访问；重设 token 后旧链接失效。
4. 完整导出 → 得到含所有简历与 meta 的 JSON，可再导入还原。
5. 删除有二次确认，且误删可撤销。

---

## 六、工程护栏

1. `meta` 加字段牵动 `save()` 白名单透传，每个字段显式加一行 + 补测试。
2. 分享静态页「已发出无法追回」的语义要在 UI 明确提示，不误导用户以为能远程吊销。
3. 新增字段遵守「四处接线」铁律 + 变异测试。
4. PII 隔离，测试数据虚构名。

---

## 七、非目标

- **不做**服务端账号体系 / 在线注册——分享仍走静态 HTML / 静态托管，不做用户系统。
- **不做**评论/批注（如需批注，另行对接飞书文档评论，不在本期）。
- **不做**访问统计 / 谁看过了我的简历。
- **本期不做** Editor 级分享权限（可编辑分享链接需要协作后端/实时同步，与「零后端」决策冲突；Viewer/Commenter 可在静态托管 + 飞书评论上实现）。三级权限仅记录为**未来演进方向**，见 §八。

## 九、实现记录与验收对照（2026-09-21）

### 落地内容

| 功能点 | 实现位置 | 说明 |
|---|---|---|
| F1 简历锁定 | `js/store/library-share.js`（判定）+ `js/app.js`（`resumeToggleLock` / `syncLockState`）+ `js/render/resume-render.js`（拖拽守卫） | 锁定态：`.editor-pane > .panel` 整体加 `inert`（鼠标 / 键盘焦点 / 读屏一并挡住）+ `body.resume-locked` 置灰兜底（老内核不支持 `inert` 时靠 `pointer-events`）；预览区**不设** `inert`（否则长简历无法滚动），改为隐藏 ↑↓ 按钮并在 `dragstart` / click 里拒绝重排 |
| F2 分享开关 | `ResumeShare.shareGate` + `js/app.js` 的 `sharePageGuarded` + `js/ui/menu-actions.js` 的 `enabled` 判定 | 未开启分享 → 菜单项**真置灰**（`disabled` + `is-disabled` 类 + `menu-desc-off` 提示「去哪开启」）；另有兜底路径（误触发时弹「现在开启并导出」的确认，而不是死路） |
| F3 唯一分享标识 | `genToken` / `ensureToken` / `tokenOf` / `tokenNote` + `js/export/export-pdf.js` | 20 位小写字母数字；写进导出页 `<meta name="resume-share-token">`；「重设标识」使之后导出的页面换标识 |
| F4 完整数据导出 | `buildBundle` / `parseBundle` / `resolveImportedParent` + `exportLibraryBundle` / `importLibraryBundle` | 整库 JSON（含 `tags` / 血缘 / `isPublic` / `isLocked` / `shareToken` / 同步指纹）；导入为**新增不覆盖**，`parentId` 按 `idMap` 重映射到新 id，母简历不在备份里则不写血缘（不留悬空引用） |
| F5 一键删除 | `ResumeLibrary.remove/beginRemoveBatch/undoRemove/peekRemoved` + `resumeRemove` / `removeAllResumes` + `.undo-toast` | 删除前把 `{meta, doc}` 存入**会话级**（内存，不进 localStorage，避免正文撞配额）撤销栈；「全部删除」两次确认，删除后 10 秒内可整批撤销 |

### 关键设计决策

1. **状态存 meta，不存 `data`**：锁定 / 分享是「这份简历的属性」，不是简历内容。存 `data` 会随内容哈希变化、触发一次多余写盘，也会被导出文件带走；因此统一走 `ResumeLibrary.patchMeta`（白名单）。
2. **白名单收敛成一份**：`save()` 与 `patchMeta()` 此前各抄一份字段列表（历史上飞书同步字段就漏过一处），本次收敛为单一 `META_PASSTHROUGH`，新增字段只加一行。
3. **删除撤销复用原 id**：血缘（`parentId`）与飞书同步分键（`file_token_<id>`）都锚在 id 上，换 id 会让派生版变孤儿、同步重新拉一份，因此 `undoRemove` 原样写回。
4. **门禁失败要放行**：`shareEnabled()` 在**任何**状态取不到的情况（单份模式 / 库未就绪 / 索引未加载 / 抛错）都返回「可用」。若实现成「取不到就禁用」，新功能会把用户的导出入口直接锁死。
5. **诚实标注 F3 的边界**：无托管后端 ⇒ token 是分享页的身份标识，而不是可远程吊销的短链。`tokenNote()` 的文案里明写「已导出的静态页发出去后无法远程吊销」——这是 §六 护栏 2 的硬要求，不能让用户误以为能撤回。

### 未做 / 边界

- **三级分享权限（Viewer / Commenter / Editor）**：按 §八 评审结论列为 P3 未来方向，本期不做（Editor 需协作后端，与零后端决策冲突）。
- **真正的「回收站」**：撤销栈是会话级内存（只保留最近一批删除），关掉页面即失效；完整回收站需要另一套 UI 与配额策略，本期不做。
- **托管后端的「链接吊销」**：见验收标准 #3，按项目形态明确不做，且已在 UI 文案中如实告知。
- **锁定态下的键盘操作**：依赖 `inert`（Chrome 102+ / Safari 15.5+，覆盖 Tauri 的 WKWebView）；老内核只有 `pointer-events:none` 一道防线，仍可能用 Tab 键进入面板 —— 已用 CSS 兜底但未做逐字段 `disabled`（成本高、收益低，记为已知限制）。
